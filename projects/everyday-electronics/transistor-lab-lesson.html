Transistor Lab — the lesson

The exhibit puts two transistors on one bench — an N-channel MOSFET and an NPN BJT — and lets you bias each one, lock it to a load line, and push it into clipping. Underneath, the two devices obey two different laws, and that contrast is the whole lesson: the MOSFET is a voltage-controlled square law — current grows as the square of how far you push the gate past threshold — while the BJT in this lab is a current-controlled multiplier — collector current is base current times a gain, β. This page is the other half of the exhibit: which models the code actually runs (measured, not read off its own labels), the numbers it produces, and where it bends away from a real device.

⚠ One name is wrong, flagged up front: this lab is NOT an Ebers–Moll model. A comment in the shipped code calls the BJT's saturation knee a “Smooth Ebers-Moll saturation knee.” It is not Ebers–Moll. The real Ebers–Moll model drives collector current exponentially from VBE — IC ∝ eVBE/VT, rising one decade per ≈59.5 mV of VBE at 300 K. This lab has no VBE input at all: you set IB with a slider and the code multiplies it by β. Driven headlessly, IC/IB is a constant 107.5 from IB = 10 µA to 400 µA — perfectly linear, not exponential in anything. The BJT half is a constant-β current-multiplier model with an Early effect and a soft saturation knee. That is a legitimate teaching model — it is just not the one the comment names. Everything else on the page that we checked matches what the code actually computes; the remaining gaps are bends, named below, not false claims.

How this audit was done

The exhibit's own JavaScript was extracted from the shipped page and run headlessly in Node, with the document, canvas and animation frame stubbed out. We then called the page's own functions — mosfetCurrent(), bjtCurrent(), mosfetGm(), solveLoadLine(), loadPreset() and updatePhysics() — set their inputs ourselves, and read back what they computed. Every “independent” column below was calculated separately from textbook formulas, never copied from the page's code. The physics core ran clean on all six presets with no errors: the exhibit functions as shipped.

Device 1 — the MOSFET is a square law, proven from its own numbers

The test that separates the models: sweep the control voltage and watch the shape. An exponential device multiplies current by a fixed factor per fixed voltage step. A square-law device adds a fixed amount to √I per step. Driven at VDS = 6 V, Vth = 1.5 V, k = 4.0 mA/V², λ = 0.025 V⁻¹, √ID climbs in dead-even steps of ≈0.758 per 0.5 V of VGS — a straight line. That is the square law, not an exponential and not a switch.

Device 2 — the BJT is a constant-β multiplier, proven from its own numbers

There is no base-emitter voltage anywhere in the BJT's current equation. What the code runs is:

IC = β · IB · (1 − e−VCE/0.14) · (1 + VCE/VA) Three factors: the β multiplier, a soft saturation knee with a 0.14 V scale, and the Early effect (VA = 80 V default). In forward active operation the knee factor is ≈1, so IC ≈ β·IB·(1 + VCE/VA) — which is exactly the formula the exhibit's own equation box prints. The box is honest; the code comment naming it “Ebers-Moll” is the part that is wrong.

With the β slider at 100, the measured gain is 107.5 at VCE = 6 V — not a bug: it is β × (1 + 6/80), the Early factor, and the equation box discloses it. But β itself never moves: no fall-off at high current (real devices lose β to high-level injection), no fall-off at low current, no temperature drift. Set the slider to 20 or 200 and the ratio scales in exact proportion (21.5 and 215.0 measured at VCE = 6 V). The “NPN BJT Gain (β=100)” preset therefore delivers a Q-point of VCE = 6.00 V, IC = 19.35 mA, P = 116.1 mW, Forward Active — as labelled, once you know the 107.5 is β wearing its Early tilt.

The on-page claim “Saturation: VCE ≈ 0.2 V, IC < β·IB” is roughly right in spirit: at 0.2 V the device has already lost a quarter of its active-region current, and driven hard against a load line (IB = 400 µA, β = 200, RL = 250 Ω, VCC = 12 V, solved with the page's own solveLoadLine()) the operating point settles at VCE = 0.126 V, IC = 47.50 mA against a load-line maximum of 48 mA — a believable saturated switch point. But treat 0.2 V as the middle of a soft knee, not a cliff: this model reaches it by an exponential-in-VCE factor with a 0.14 V scale, an invention for smoothness, not a junction law.

The VBE that isn't there

A real BJT's defining curve is IC vs VBE: exponential, ≈59.5 mV per decade of current at 300 K (VT·ln 10, with VT = 25.85 mV — a value the code itself uses correctly for gm = IC/VT). This lab never computes current from VBE. The only VBE in the code is a display-side estimate used to draw a depletion width, VBE ≈ 0.70 + 0.048·ln(IB/100 µA), and driven through updatePhysics() it climbs 110.5 mV per decade of IB (0.590 V at 10 µA → 0.700 V at 100 µA → 0.811 V at 1000 µA) — nearly twice the physical slope, consistent with a natural log used where a decade log was intended. It is never shown as a readout, so no number on the page is wrong because of it; but do not learn the VBE slope from this exhibit. Learn it from the references below.

Bends named honestly

Not Ebers–Moll (the flag at the top). The BJT takes IB as its input and multiplies. A real base is driven by VBE, and IB is itself an exponential consequence. Everything the lab teaches about β, load lines, Early effect and saturation clipping survives this bend; anything about why a base sits near 0.7 V does not live in this exhibit.

β is a constant you set. Real β varies with current, temperature and the individual transistor — which is why real bias circuits are designed to survive β changing by 3×. Here β is a slider (20–200) and the ratio IC/IB tracks it exactly, tilted only by the Early factor (1 + VCE/VA).

The BJT gain Av is a system gain, not the intrinsic stage gain. The page feeds the AC input to the base through a fixed 5,000 Ω resistor, so its displayed Av ≈ −β(RL‖ro)/5000 ≈ −5.6× for the BJT amp preset. The intrinsic common-emitter gain at the same Q-point, −gm(RL‖ro) with gm = 750 mS, is ≈ −210×, and the device's own input resistance rπ = β/gm ≈ 133 Ω — not 5,000 Ω. Both numbers are “the gain” of something; know which circuit each belongs to. The diagnostics panel's measured gain (−6.06× for that preset) is the honest one for the circuit as wired, and in the clipping preset the displayed Av (−6.47×) stays at its small-signal value while the measured gain collapses to −3.59× — read the measured one when the waveform is clipped.

Sharp cutoffs, no leakage. The MOSFET conducts exactly zero below Vth (driven: ID = 0 at VGS = 1.2 V) — a real device leaks exponentially in subthreshold, which is where the BJT-style exponential actually lives in a MOSFET. The BJT likewise returns exactly 0 for IB ≤ 0.2 µA at any VCE: no ICEO leakage.

The printed triode equation drops λ. The on-page MOSFET equation box omits the (1 + λVDS) factor in the triode region, but the code applies it there too. The printed formula under-reads the driven current by 2.5% at VDS = 1 V and 6.25% at the triode/saturation boundary (12.500 mA printed vs 13.281 mA driven at VDS = 2.5 V). The saturation formula on the same box, λ included, is exact.

Three saturation borders on one page. The region classifier calls a BJT saturated below VCE = 0.42 V, the equation box calls it forward-active above 0.35 V, and the graph shades the saturation zone below 0.38 V. All three are defensible places to draw a soft knee's edge — but they are three different numbers, and the knee itself (0.14 V scale) is smoother than any of them suggests: effective β is already down to 92 at 0.35 V and still only 95.5 at the classifier's 0.42 V border.

Stale placeholder telemetry in the static HTML. The page as first written shows ID = 12.50 mA, P = 75.0 mW and Av = −2.88× — the values the default bias would give with λ ignored (½kVov² = 12.5 mA, −gmRL = −2.88×). The running code corrects all three on its first frame (14.375 mA, 86.2 mW, −2.64×), so you will likely never see the stale set — but the file's first impression is the λ-free approximation, not the model it runs.

Also simplified, briefly: no body effect or mobility degradation in the MOSFET (k is constant), no base resistance or junction capacitance in either device, no breakdown at high VDS/VCE, and the LED load is a fixed 2.0 V drop. The load-line solver itself — a 28-step bisection for the exact device/load intersection — is the real thing, and the saturated switch point it finds (0.126 V) is honestly earned from it.
