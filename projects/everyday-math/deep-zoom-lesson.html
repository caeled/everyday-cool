Deep Zoom — the lesson

Deep Zoom is a diving bell for the Mandelbrot set. One tiny rule — take a number, square it, add the same constant, repeat — paints a coastline of endless detail, and this explorer lets you fall into it: drag a box and drop, scroll and sink, past the point where ordinary computer arithmetic dissolves, down to a hard stop at 1050× magnification. Beside the main view, a second window shows the Julia set for whatever point your cursor is touching, morphing live as you move — because the Mandelbrot set is not just a picture. It is the map of all those other pictures. This page is the other half of the exhibit: the mathematics, the audit that checked the explorer's claims against its own code, and the one number on its honesty card that turns out to be a fence the builders installed rather than a cliff the arithmetic found.

Deep Zoom was built by Google Antigravity (Gemini) at Steven Powell's direction; this lesson and its audit were written by Muse, from reading the explorer's code and running its iteration engines headlessly against an independent implementation.

The mathematics

One rule, two fates

Every pixel on the screen is a complex number c. The machine starts at z = 0 and applies one rule, over and over:

z → z² + c For most values of c the orbit runs away to infinity. For some it stays trapped forever, orbiting or settling. The Mandelbrot set is exactly the set of c whose orbit never escapes — painted black. Everything jewel-coloured around it is the outside, shaded by how long the orbit took to flee.

Escape is a theorem, not a guess: once |z| passes 2, the squaring grows faster than c can pull back, and the orbit is guaranteed to diverge. So the machine only has to watch for the orbit to get big, not infinite. How big the bouncer's line is — 2, or larger — turns out to matter to the bookkeeping, and the audit has something to say about it below.

The boundary is where the mathematics lives

Deep inside the black, nothing happens. Far outside, orbits leave immediately. All the filigree — the spirals, seahorse tails, and filaments — lives on the boundary, where orbits hesitate for hundreds or thousands of steps before deciding. Zooming in never smooths that boundary out: it is detailed at every scale, decorated with near-copies of the whole set that are similar but never identical (the copies are warped, and each sits in a different neighbourhood). Scattered along the filaments are minibrots — true miniature Mandelbrot sets, complete with their own cardioids and bulbs. There are infinitely many. A deep-zoom explorer is a machine for visiting a few of them.

The Mandelbrot set is a map of Julia sets

Run the same rule the other way around — fix c, and let every starting point z0 in the plane be a pixel — and you get a Julia set. There is one Julia set for every point in the plane, and the great theorem connecting them (Fatou and Julia, a century ago) is exact: a Julia set is one connected piece if and only if its c lies inside the Mandelbrot set — equivalently, if and only if the orbit of 0 under that c stays bounded. Pick a c in the black and its Julia set is a single lacy island; pick a c outside and the Julia set shatters into dust. That is what Deep Zoom's second window is showing you as your cursor crosses the coastline: connected lace dissolving into dust and knitting back together, with the boundary of the Mandelbrot set as the exact border between the two behaviours. The map is the territory's index.

Smooth colouring: fractional escape

Raw escape counts are integers, and integer counts paint hard bands. The standard cure is a fractional escape value: when the orbit escapes, how far past the line it jumped tells you how far between two integers it really belongs. Deep Zoom computes

ν = n + 1 − log2( log2 |z| ) n is the step on which the orbit escaped and |z| is its size at that moment. The double logarithm compresses the enormous overshoot of a squaring map into a gentle fraction. ν is genuinely continuous — neighbouring pixels get neighbouring values — and the audit verified the formula is the one the code runs, in all three of its engines.

Floating point: the machine's physical limit

An ordinary computer number (an IEEE-754 double) carries 53 bits of mantissa — about 16 decimal digits of precision. A pixel's address is computed as centre + offset, and when the offset shrinks below the centre's last representable digit, adjacent pixels round to the same address: the picture pixelates into blocks no matter how long you iterate. With a view 3.5 units wide and a few hundred pixels across, that wall stands somewhere around 1013–1014× magnification — the audit measured it for this explorer's own view math below. Real deep-zoom tools (the lineage of Kalles Fraktaler and its kin) break through with perturbation theory: compute one orbit — the view centre's — in very high precision, then compute every pixel as a small difference from that orbit, using a recurrence for the differences that only needs ordinary arithmetic. Differences stay representable long after absolute addresses stop being. When a pixel's difference grows as large as the orbit itself, the approximation is rebased — restarted from the pixel's own current position — a refinement associated with Zhuoran Gu. Deep Zoom implements exactly this machinery, which is the audit's headline: the commission allowed it to simply confess a 1014 floor, and instead it built the real engine.

The audit — claims checked against the code, with receipts

Deep Zoom arrived with a commission: honest per-pixel iteration, smooth colouring, iterations that rise with zoom, a live Julia link, an honestly stated precision floor, bookmarks that frame what they name, and a dive game scored on real magnification. The audit extracted the shipped engines — the Float64 iterator, the perturbation iterator, the Julia loop, and the 256-bit BigInt arithmetic — and ran them headlessly against an independent iterator written for the audit.

The convention divergence: the commission specified an escape radius of 2 (|z|² > 4). The shipped code uses a bailout of |z|² > 256 — |z| > 16 — in every engine (and 65,536 when deciding where its reference orbit ends). A larger bailout is a legitimate, even preferable, technique: the smooth-colouring formula is more accurate when the orbit escapes decisively. But it is a different counting convention: an orbit must travel further before the bouncer acts, so escape counts run slightly higher than the textbook radius-2 count for the same pixel (for c = 1, the smooth value is 1.767 under the shipped convention against 1.785 under radius 2, because the orbit is caught at a different step and distance). Nothing is faked — but if you compare Deep Zoom's counts against a book's, expect the small, explainable offset.

Receipt 2: the perturbation engine agrees with the direct engine

It computes one reference orbit in 256-bit fixed-point BigInt arithmetic, then iterates each pixel as a difference from that orbit, rebasing whenever the difference grows to rival the orbit itself. The genuine soft limits at depth are murkier than any single number: the reference orbit's values are stored as ordinary doubles (standard practice — the orbit is a size-~1 object, where doubles are fine-grained), pixel differences are doubles, and the telemetry readout and minibrot detection quietly collapse the centre back to a double to do their comparisons. None of that makes 1050 wrong as a stopping place. It makes it a policy — and the honesty card presents it as physics ("where 256-bit digits & Float64 delta squares bottom out"). At 1050×, a pixel difference is ~10−50 and its square ~10−100; doubles reach to 10−308. The bottoming-out story is the one bend in an unusually straight honesty card, and it is named here.

How it's built — the coding choices

Three engines, one counting house

Below 1012×, pixels iterate directly in doubles, with an exact algebraic skip: points inside the main cardioid or the period-2 bulb are declared interior without iterating — a theorem, not a shortcut, and the audit's grid agreement confirms it changes nothing. Past the threshold, the BigInt reference orbit and perturbation take over, with rebasing. The Julia window has its own simpler loop — it checks escape before each step rather than after, so its fractional value is written n − log2(log2|z|) instead of n + 1 − …; the two formulas are the same count kept from opposite sides of the step, and the audit's probes confirm the Julia loop draws the theory's lines in the right places. All three engines share the palette machinery, so a point's colour means the same thing in every window and at every depth.

Iterations: the commission asked for a ramp; the build ships a dial

The commission required maximum iterations to rise automatically as magnification deepens. It does not. Max iterations is a manual slider (80–4,000, default 500), and zooming — by wheel, box, or button — never touches it. The only places the number changes hands are the slider, the dive sites (each carries its own count, 500–2,800), and bookmarks, which remember the count they were saved at. In practice the curated depths arrive pre-sharpened, but a free dive past 106× on the default 500 will show filaments dissolving into false black that a higher count would carve open — and the honesty card's own line admits the mechanism ("points still bounded at Max Iterations are painted black") without admitting the missing ramp. The Julia window, for its part, runs at 60% of the main count, clamped between 140 and 360.

Progressive rendering, and colour kept separate from truth

The Mandelbrot view renders in three passes — every 4th pixel, then every 2nd, then all — in 11-millisecond slices, so a dive sharpens progressively instead of freezing the page. The smooth escape values are cached in a buffer, and the colour of a pixel is a pure function of that cached value: the palette's position is computed as (log(ν + 1) × 0.22 + ν × 0.0045 + phase) mod 1 through a 2,048-entry lookup table whose first and last colours match, so hues cycle seamlessly — the "Breathe" mode simply advances the phase and re-colours from cache without re-iterating a single pixel. ν itself is continuous (Receipt 1), so there are no false bands in the data; the repeating jewels are the palette's deliberate cycle, not the mathematics stuttering.

The dive game and the log

Four challenges: centre Seahorse Valley at 40× or better (the one true centredness test — the view's centre must land within 0.045 of (−0.7453, +0.1127), about one half-width at that zoom); reach 106× anywhere — its own hint says "anywhere," and the code agrees: no feature need be in frame, a dive into empty exterior at a million× counts; find a minibrot (within a stated radius of a listed site at its minimum zoom); and cross 1014×. The commission also asked for a ×1,000 challenge — there isn't one. All checks consume the renderer's own view.zoom and the centre collapsed to a double, which at these radii (the tightest is 0.005) loses nothing. The dive log, kept in your browser under one localStorage key (deep_zoom_dive_log_v1), records the deepest zoom with its coordinates as exact decimal strings — with one quirk: a new depth is only logged when it beats the stored one by more than 5%, so the log can lag a personal best by up to that margin. Bookmarks (up to 16) store the same exact strings and restore them losslessly through the BigInt parser the audit round-tripped.

Simplifications and divergences, named

The game's own honesty card, checked line by line: "Colour is escape speed, not the set" — true, and the interior is painted pure black. "Finite iteration horizon" — true, and admitted with its remedy. "Plain doubles hit pixelation around 1014×" — the right order of magnitude; the audit's figure for this view math is 2–3.3 × 1013×. "Past 1012×, a 256-bit BigInt reference orbit + Zhuoran rebasing perturbation" — true, verified in the code and by engine-against-engine rendering. "The real set continues forever past any zoom we can compute" — true, and the right note to end on.

The floor is a fence, not a cliff: the card says the depth extends to ~1050× "where 256-bit digits & Float64 delta squares bottom out." Neither bottoms out there — the 256-bit centre has resolution 2−256 ≈ 8.6 × 10−78, and delta squares at that depth are ~10−100 against a double floor of 10−308. 1050 is MAX_ZOOM, a constant the zoom gestures clamp to. A sensible fence — past it, the double-precision reference orbit and detection arithmetic would need their own audit — but the card tells it as a limit of the mathematics, and it is a limit of the build.

The bailout is 16, not 2: escape is declared at |z| > 16 (|z|² > 256), not at the commissioned |z|² > 4. Better smooth colouring, slightly different counts than the textbook convention — named in Receipt 1, and the reason a hand-check against a book's escape table will differ by a step here and there.

Iterations never rise on their own: the commissioned automatic ramp is absent; the count is a manual slider plus per-site presets. Deep free dives on the default 500 iterations will paint escapable filaments black — the card admits the horizon, not the missing ramp.

The dive game's million× needs no feature: of the challenges, only Seahorse Valley and the minibrots test where you are; the 106× and 1014× challenges test only the zoom dial. There is no ×1,000 challenge. The dive log's 5% hysteresis means a logged "deepest" can sit up to 5% below a depth actually reached.

Small print: the reference orbit is computed in 256-bit fixed point but stored as doubles — standard perturbation practice, and one reason the deep engine is an excellent approximation rather than an exact one (Receipt 2's single glitch pixel is its signature). The telemetry readout and minibrot detector read the centre through a double, so at extreme depth the displayed coordinates carry fewer digits than the engine's own address — the bookmarks, which store the decimal strings, are the precise record. And the explorer's default Julia set, for the seahorse spiral it opens on, is — by the theorem the page teaches — dust, not lace: c = −0.7453 + 0.1127i is an exterior point whose orbit escapes in ~74 steps. It is beautiful dust, and the distinction is exactly the lesson the linked window exists to teach.
