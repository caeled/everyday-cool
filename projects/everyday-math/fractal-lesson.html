Everyday Math · The lesson behind Fractal

Fractal: one line of maths, endless coastline

The Mandelbrot set is what you get by asking, for every point c in the complex plane, a single question: if you start at zero and keep applying z → z² + c, does the orbit run away to infinity, or stay bounded forever? The points that stay are the set. The points that run carry a number — how long they took to escape — and that number, coloured by a rotating palette, is the picture.

Written by Steven Powell in Python (his Bordeom workshop); web port by Muse, maths carried over line for line. The original runs on numpy and pygame; this page runs the same code in your browser, and the proof table below is the original's own self-test, run against the shipped code.

The escape-time picture, and how the colour stays smooth

Steven's compute() is the textbook escape-time algorithm with three refinements that matter. First, the bailout radius is huge — a point counts as escaped only when |z|² passes 65536, i.e. |z| passes 256, not the usual 2. Second, the colour is a smooth count, not a whole number of iterations:

nu = i + 1 − log₂( 0.5 · ln |z|² )

The correction term measures how far past the bailout the orbit had already travelled, which is what turns banded steps into flowing gradients. The big bailout is what makes the correction accurate — at radius 2 the formula is a rough guess; at 256 it is nearly exact. Third, two shortcuts keep it fast: points inside the main cardioid or the period-2 bulb are known members of the set by a closed-form test, so they are never iterated at all, and pixels that escape are dropped from the working set as they go, so a deep frame's cost follows its few detailed pixels instead of the whole 64,000. The smooth count is multiplied by 5 and wrapped into a palette index — the palettes themselves are Warp's: in the Python, fractal.py literally does from warp import PALETTES, and both web pages carry the same palette module. Colour rotation then animates the still picture for free, exactly as in Warp.

Depth costs iterations

Zooming in is not free: the closer you look, the longer orbits take to escape, so the iteration budget has to grow with depth or deep views dissolve into mush. Steven's rule is linear in doublings:

max_iter = min( 4000, 96 + 42 × log₂(home scale ÷ scale) )

The proof table checks the budget at five scales against the Python's own numbers — 99, 378, 936, 1494, 2611 — and they match to the digit, cap included. The dive mode spends that budget on a tour: it falls toward one of six target valleys at 0.9 doublings per second until each pixel spans 2×10⁻¹¹ of the plane, holds four seconds, fades, and picks the next valley and a new palette. The six targets — Seahorse valley, Triple spiral valley, Spiral, Deep spiral, Elephant valley, Misiurewicz spirals — were found by computation, not looked up: each was refined by zooming repeatedly toward the most detailed pixel, and the proofs re-verify them every load: at a scale of 1e-9 each one must still show at least 100 distinct colours with less than 90% of the frame inside the set. Pressing J over any point swaps the question: now c is fixed and every pixel is a starting z — the Julia set for that c. The proof that the machinery is right is the oldest one there is: for c = 0 the Julia set must be exactly the unit disk, and it is.

How fast is the classic view?

The Python's docstring brags that the classic 320×200 view takes about 13 ms — on Steven's own machine. Measured on the porting bench (a small shared VM, not his machine), the same view took 67 ms in the Python and roughly 30–70 ms in this port's JavaScript across repeated runs — the page's own proof row measures it live on your machine every load, which is the number that counts. Either way, the honest comparison is the one the original makes: in the 1980s this picture took minutes to hours and wanted a maths coprocessor; now it is a rounding error in a frame budget, in two languages.

The honest notes. There is a floor, and the page names it instead of hiding it: coordinates are float64, and the zoom clamps at a pixel size of 1e-13 complex units (MIN_SCALE). Deeper than that, neighbouring pixels would round to the same representable numbers and the picture would dissolve into blocks — the floor is where the number format runs out of digits. Arbitrary-precision zoomers exist that sail past it by carrying hundreds of digits; this one is a float64 machine and says so. Two smaller porting differences: the Python stores its smooth counts in float32 where the port uses float64 — one notch more precise, so a colour index can differ by one at a band edge and nothing else moves — and deep in a dive the page draws at half resolution while a full frame would take over 300 ms, refining back when the cost allows, which is the Python original's own adaptive step, thresholds included. The screenshot key downloads through the browser where the Python saves a file beside the script; the picture saved is the same canvas either way.
