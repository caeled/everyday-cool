Everyday Math · The lesson behind GaussLab

GaussLab: pick your variables, feed the grid, watch it solve — audited to the last fraction

On the morning of 25 November 2026, Steven commissioned Antigravity to build the thing he had wanted since algebra class: a real matrices workbench. Choose how many variables you have, type in a system, and watch the grid solve it — again and again, one honest row operation at a time, with the deep reference chapters riding alongside. This page is the audit of that build: what it claims, what we measured driving the shipped file through its own buttons and input cells, and the few places where its teaching copy bent — all four found by the audit, all four fixed at Steven's word the same morning, each recorded below with its measurement.

What the bench is

GaussLab is a single self-contained page (166,782 bytes, no external requests) holding a complete linear-systems laboratory. Systems run from 2×2 up to 6×6, square or rectangular (2–6 equations in 2–6 unknowns). Four solution methods share one grid: Gauss–Jordan (RREF), Gaussian elimination with back-substitution, Cramer's Rule, and the Inverse Method. Every step of every method is a playable card: a stated row operation, the matrix it produces, and a per-cell arithmetic strip showing each entry being computed. A manual sandbox lets you apply your own row operations (and refuses illegal ones, out loud). A geometry canvas draws the equations as lines or planes that morph as you step, telemetry reports rank, determinant, nullity, trace and condition number, and eight reference chapters plus a sixteen-term glossary carry the explanations. Eleven curated presets — Kirchhoff loops, chemical balancing, a Hilbert matrix, a 5×5 heat plate, a 6×6 truss — load in one click.

The engine room matters: the bench does not solve in floating point. Every entry is an exact BigInt rational, so a displayed 1/2160 is exactly 1/2160, and the partial-pivoting row swaps it performs are the real LAPACK habit, not decoration.

What's real

The arithmetic is exact, not approximate. Solutions, determinants, inverses and condition numbers are computed in BigInt rationals and displayed as fractions; nothing in the solving path is a rounded float.

The steps are the lesson. Because every printed operation was verified to produce the next printed grid, a learner stepping through GaussLab is watching the actual computation — the same claim this room's lessons make, here measured 90 operations deep.

The geometry is honest. The canvas re-draws from the current step's grid, so the lines genuinely morph through the elimination and stay pinned through the solution — and the bench says so only because it's true.

Failure is reported, not hidden. Singular, inconsistent and underdetermined systems each get their true fate, in words, with the ranks that prove it.

What bends

Four findings, none in the solver, all in the copy or the input cells. GaussLab is a guest build, and the house rule is that guest files ship byte-for-byte — but on 25 November 2026 Steven sanctioned the banner and all four fixes (“you can fix it. then get it wired.”). Each bend below keeps the audit's original measurement, then records the fix that was applied and how it was re-verified.

1 · A typo in a cell silently becomes 0. Type letters into a coefficient cell — we typed abc — and the bench quietly replaces the entry with 0 and re-solves the new, different problem, with no warning anywhere on the page. An emptied cell does the same. On a teaching bench, a dropped minus sign is the classic accident; a silent zero is the one accident the bench itself should catch. (Measured: the cell reads back “0” and the solution updates to match the zeroed system.)

Fixed — 25 November 2026, at Steven's word. A cell now checks its entry before accepting it: letters, an emptied cell, or a fraction with a zero denominator keep the last valid value, mark the cell in red, and print a plain note — “abc” isn't a number, so that cell kept its previous value (2). The problem hasn't changed. Spot-audit after the fix: typing abc and emptying a cell both left every value and the displayed solution untouched, with the note showing; a valid entry clears it.

2 · Chapter 4 explains infinite solutions with the wrong mechanism. Fate 2 says:

“At least one equation was redundant (a secret combination of the others), turning into 0 = 0.”

That is true of dependent square systems, but it is not why systems have infinitely many solutions in general — and the bench itself proves it: load two independent equations in three unknowns and there are infinitely many solutions with no redundant equation and no 0 = 0 row anywhere. The real condition is the one the same chapter states correctly a breath earlier: rank(A) = rank([A|b]) < n — fewer pivots than variables, so some variables are free.

Fixed — 25 November 2026. Fate 2 now teaches the general condition: the elimination runs out of pivots before it runs out of variables — rank(A) < n — whether that is a redundant equation collapsing to 0 = 0 or simply fewer independent equations than unknowns from the start. The card's own rank condition line was already correct and stands unchanged.

3 · Chapter 5 hangs Cramer's definition on the cofactor formula. The 3×3 expansion is printed as:

“det(A) = a₁₁·M₁₁ − a₁₂·M₁₂ + a₁₃·M₁₃ where Aᵢ is built by replacing column i of A with vector b!”

The expansion itself is correct, but the “where Aᵢ…” clause belongs to Cramer's Rule, not to the minors Mᵢⱼ it sits on. A learner reading it as the definition of the M's will build the wrong matrices. The clause is true — one paragraph too early.

Fixed — 25 November 2026. The stray clause is removed; the cofactor expansion stands on its own, and Aᵢ keeps its correct definition where it belongs — the glossary's Cramer's Rule entry (“replacing column i of A with target vector b”), which the audit verified is stated correctly there.

4 · One preset promises 0 = 4; the bench answers 0 = −4. The “No Solution (Contradiction)” preset advertises “Exposes the impossible 0 = 4 row”, and the combination Row 3 − (Row 1 + Row 2) does give exactly 0 = 4. But the bench's own elimination path reaches the contradiction as 0 = −4, which is what its solution panel prints. Both are the same impossibility — the sign depends on the road taken — but a learner comparing the preset's promise with the panel will think one of them is wrong.

Fixed — 25 November 2026. The preset now promises what the bench prints: “Exposes the impossible 0 = −4 row”. Verified after the fix by driving the preset to its final frame — the panel reads “Row reduction uncovered a contradiction in Row 3: 0 = −4”, and the final grid's third row is 0 0 0 −4. Promise and panel agree word for word. The solver was not touched.

Two smaller notes, recorded rather than counted as bends: decimal display mode rounds to 4 places (1/3 shows as 0.3333) without an ≈ marker — fraction mode, the default, is the exact one. And the 3D geometry was verified at presence level — all three planes render from the live step grid, and the drawing code reads each plane's equation from the current row — rather than pixel-by-pixel as the 2D canvas was, because projection and translucent fills make pixel sampling a weaker instrument there.

Verdict: the mathematics of GaussLab is exact everywhere the audit could measure — solving, stepping, determinants, inverses, geometry, and all eleven presets. The bends live in three sentences of teaching copy and one silent input behaviour. That is a strong guest build. Steven sanctioned all four fixes the same morning; they are applied, spot-audited, and entered in the edit record below.
