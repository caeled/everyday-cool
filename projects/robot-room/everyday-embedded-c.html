What you are looking at

A microcontroller on a bench — a model of an ATmega328P-style chip (the chip inside an Arduino Uno), simplified to the parts this workshop needs. Real robot brains are programmed in C, and the C talks to the hardware through registers: bytes inside the chip whose individual bits are switches. Flip the right bits and a pin becomes an output, an LED lights, a hardware timer starts counting, and a motor pin starts pulsing — all without the code doing the work itself. This bench lets you flip those bits with your mouse and watch the pins obey.

The three stages

  • Stage 1 — Blink. The "hello world" of hardware. Set one direction bit, flip one port bit in a loop, and an LED blinks. The pause between flips is a delay loop: the chip sitting and counting to itself.
  • Stage 2 — The cost of waiting. A delay loop is the chip doing nothing, expensively: at 16 MHz a half-second delay burns about eight million clock cycles, and while it counts, it cannot watch a sensor. The sensor-blip lab shows a polling program missing events it would have caught with a shorter loop.
  • Stage 3 — The timer does it. Timer2, a counter built into the silicon, counts clock ticks on its own. Set its mode and prescaler registers and it blinks a pin in CTC mode, or produces PWM — a fast on/off wave whose width you set with one compare register. That wave dims the LED and drives the motor bar, which is exactly how the Motors workshop gets its speed control.

How to use the registers

  • Every register is drawn as eight bit boxes, bit 7 on the left. Click a box to flip the bit. The register's value (hex and binary) updates, the pins obey instantly, and the bit's plain-language meaning appears in the dashed box under the stage.
  • Greyed-out bits are reserved on the real chip — the datasheet says leave them at 0, so the bench won't let you set them either.
  • Stage 1's code pane steps: press Step and the matching line runs on the model — registers flip, cycles burn. Stage 3's code pane is the other way round: it generates the C from the registers you set, so the code you read is always the code your bits mean.

The numbers, so you can check them

  • The chip clock is 16 MHz — 16,000,000 ticks a second, the Uno's crystal.
  • Fast PWM frequency = 16 MHz ÷ (prescaler × 256). Prescaler 64 → 976.5625 Hz.
  • Fast PWM duty = (OCR2B + 1) ÷ 256. OCR2B = 127 → exactly 50%.
  • CTC toggle frequency = 16 MHz ÷ (2 × prescaler × (1 + OCR2A)).
  • Those are the datasheet formulas for Timer2, and the proofs panel at the bottom re-checks the bench against them, live, when you press its button.

The Arduino contrast

On an Uno, analogWrite(3, 128) does Stage 3 for you: pin 3 is this bench's PD3, and the Arduino core sets these same Timer2 registers (phase-correct mode, prescaler 64, about 490 Hz) and writes your number into OCR2B. The training wheels are real — they just hide the registers. This bench takes them off so you can see what was always underneath.

One honest note

This is a model of one chip family, simplified on purpose: one port, one timer, no interrupts, no analog input. Those are the next doors, and the lesson page names them rather than pretending they are in here. The code panes show and step C — they are not a compiler, and nothing is uploaded anywhere. Deeper PWM theory lives in the Power & PWM bench in Everyday Electronics.

Everyday Embedded C — blink to PWM, at register level

Robots run on little chips, and little chips are programmed one register at a time. Start where every embedded programmer starts — blink an LED — then feel why the delay loop that blinks it is a trap, then hand the job to the hardware timer and watch one compare register become a dimmer, and then a motor control. Every number on this bench is computed from the register bits in front of you.

The eight dots are Port D. A pin only lights its dot when its direction bit says output — an input pin drives nothing, whatever its port bit says. That one rule explains half of all "my LED won't light" bugs in real embedded work.

STAGE 1

Blink — two registers and a loop

A pin can't drive an LED until its direction bit says output — that's DDRD (Data Direction Register, Port D). Once it is an output, its PORTD bit is the voltage on the pin: 1 = 5 V, 0 = 0 V. Blink is just flipping that bit, waiting, flipping it back. Click the bits, or step the C.

STAGE 2
The cost of waiting — delay loops waste the chip

    
Make the Stage-1 delay tiny — 1 ms — and the LED blinks
    500 times a second: far too fast to see, so it just looks steadily half-lit. You have
    accidentally invented PWM, by hand, at the cost of the entire chip: while _delay_ms
    runs, the CPU can do nothing else — it can't read a sensor, steer a motor, or notice a
    button. The lab below makes that cost visible. A sensor blips five times in five seconds, each
    blip lasting 250 ms. A polling program can only notice a blip if it happens to look while the
    blip is on. How often it looks is set by its delay loop.

STAGE 3
Hand it to the timer — hardware PWM

    
Timer2 is a counter built into the silicon. It counts CPU
    clock ticks — slowed by a prescaler you choose — and when its count matches a
    compare register, it flips its pin, all by itself. The CPU sets it up once and walks away.
    In CTC mode it blinks pin D3 with no loop at all. In Fast PWM mode it produces the
    wave drawn below: on at the bottom of every count, off at the match — so the compare value
    is the duty cycle, and the duty cycle is the LED's brightness and the motor's speed.
