What you are looking at

A small two-wheeled robot on a tabletop world, and a code editor. The code you write is really run — this page contains a small interpreter for a beginner subset of Python, written for this page. It is not CPython and it cannot run arbitrary Python; it runs exactly the subset below, and nothing else. When your program calls a motor function, the simulated robot moves; when it reads a sensor, it reads the simulated world. There is no trick panel and no canned animation — the proofs at the bottom run the same interpreter and the same world that your code drives.

The robot's whole API — four functions

read_distance() — units of clear space straight ahead, measured from the robot's centre to the nearest wall or the table edge.
read_light() — a two-item list [left, right] from the two downward light sensors at the robot's front corners: 100 when a sensor is over the dark line, falling to 0 off it.
set_motors(left, right) — wheel speeds, each from -200 to 200 (the page clamps anything outside). Calling it lets one tick of time pass: dt = 0.05 s of robot time.
stop() — both wheels to zero; also lets one tick pass.

How the robot moves

Differential drive, the way almost every small robot actually moves. Forward speed is the average of the wheels, v = (left + right) / 2; turn rate is their difference over the distance between the wheels, ω = (left − right) / 40 in this page's screen coordinates (y grows downward, so a faster left wheel veers the robot right/clockwise). Each tick the page integrates one step: θ += ω·dt, then x += v·cos θ·dt, y += v·sin θ·dt. Time passes only when a motor function is called — a loop that never commands the motors never moves the robot, exactly like real code that never reaches its motor call.

The language subset

Variables and assignment (x = …); numbers; arithmetic + − * / // % (/ is true division, // floor division, % Python-style modulo); comparisons == != < <= > >=; and, or, not; if / elif / else; while; break; pass; lists like [10, 20] and indexing s[0]; comments with #; indentation with spaces, like real Python. Not included: def, for, strings, classes, imports. If your code uses them, the page says so, with the line number.

The step cap — stated plainly

Every statement your program executes counts as one step. After 2,000 steps the interpreter stops the program and tells you, instead of looping forever. A runaway while on a real robot drains the battery or drives into a wall; here it costs you one clear error message. The cap is 2,000 — the proofs below trip it on purpose and count the steps.

How to play

Pick a mission. Each loads starter code that works — press Run and watch it solve the mission, read the sensors live in the readouts, then change one number and run it again. Step executes one statement at a time so you can watch the loop think. Mission 1: reach the green goal band without touching the far wall — your only sensor is distance. Mission 2: follow the dark line to the goal; the bench counts what fraction of the trip your robot's centre spent on the line, and asks for at least 60%. Mission 3: a box blocks the straight road — drive at it, turn, hop over the top, turn back. When a run completes a mission the bench stops it and says so; a program that loops forever is stopped by the step cap instead.

Honest bends

The sensors are perfect: no noise, no flicker, no delay, and the wheels do exactly what they are told, instantly. Real sensors stutter and real motors lag — the lesson page talks about what that changes. The robot cannot slide sideways and does not model wheel slip or battery sag. The distance reading is taken from the robot's centre, not from a sensor on its nose. And the interpreter is a teaching subset: real Python is bigger, and on a real robot this same loop shape usually runs in MicroPython on a microcontroller — the lesson page points at the doors.

Everyday Python Robotics — sense, decide, act: the only robot program there is

Every robot program ever written has the same skeleton: read a sensor, make a decision, command the motors — then do it again, forever. This bench lets you write that loop in real (small) Python and watch a robot obey it: badly when your code is wrong, well when it is right. Three missions, four functions, one honest interpreter.
