🏃 The State Code — freeze the machine, hand it on

A state code is this exact console’s whole memory at one instant, written as text. Codes are married to this core build — a code from another emulator won’t load here, and this one won’t load there.

The machine

The Sega Genesis (Mega Drive outside North America) — Sega’s 16-bit machine, 1988 in Japan, 1989 here — rebuilt as software: the Genesis Plus GX core (Charles MacDonald’s Genesis Plus, carried forward by Eke-Eke — the core the whole emulation world trusts for this machine) running under the EmulatorJS 4.2.3 frontend. Both were copied into this room ahead of time (the folder emulatorjs-genesis/ beside this page), so the console plays with no network at all. The same core also emulates Sega’s 8-bit machines, the Master System and the Game Gear — those get their own cabinets on this shelf another day; today the Genesis and its CD door.

The cartridge slot

Takes .md, .gen, .smd, and raw .bin cartridge images, or a .zip holding one. A Genesis cartridge needs no BIOS — the machine’s boot code is its own — so the slot and the Start button are the whole ceremony. The file is read locally and never leaves your machine.

The Sega CD door

The Sega CD (1991) was a CD-ROM drive that clipped onto the Genesis — and unlike the cartridge slot, it cannot wake up without its BIOS: the firmware that draws the CD player’s own screen. That firmware is Sega’s, so it is not bundled — bring your own copy (usually a 128 KB or 256 KB .bin) and pick its region; the page wraps it under the exact name the core looks for (bios_CD_U.bin / bios_CD_E.bin / bios_CD_J.bin) and hands it over without changing a byte. The disc slot takes .iso, .cue, and .chd images, or a .zip holding a cue sheet and its bin. Press Start on the CD door without a BIOS and the page will tell you plainly what’s missing — the real machine sat dark the same way.

The picture’s size

Standard / Large / Extra large are three stops for the cabinet, Full screen gives the stage the whole monitor, and Pop out lifts the stage out of the column into a wide overlay (handy on a narrow window) — Pop back in sets it home. The game never restarts and the cartridge never moves; only the furniture changes size.

State codes

The Genesis core freezes and restores its whole state, so this console speaks State Codes — the panel below the public shelf. Export writes the frozen machine as a GENSTATE1: code; Import stands the machine back in it. A Genesis state is the whole 16-bit machine frozen: the audit’s exported code ran 1,381,762 characters (about a megabyte), so treat a state code as a small file to save and pass along, not a line to paste into a chat. A code only loads against the same cartridge on this console’s core build.

Where this console can live

On the live site and anywhere the room’s folder is served over the web, it plays. It does not run as a lone saved file (file://): the frontend fetches its core with requests a browser refuses from a bare file — open it from the website, or serve the folder (the Baton Box serves it), and the cabinet lights up. Unlike its DOS shelf-mate, this core is not one of the frontend’s threaded cores, so it needs no special server headers — an ordinary page on an ordinary host is enough, which the audit verified by booting it on a headerless local server.

The fine print, in the open

Genesis Plus GX is not GPL software: its own license (carried verbatim in the rack) permits redistribution non-commercially only, with its notices kept — a personal shelf like this one is the use it contemplates, and the lesson tells the whole story. The EmulatorJS frontend is GPL-3.0. No game, BIOS, or disc is bundled, hosted, or fetched by this page — the public shelf buttons open the Internet Archive’s own player, in the Archive’s house. Your files stay on your machine.

On a touch screen: the emulator draws its own on-screen gamepad — if it is not showing, tap the controller button at the edge of the player.
