X-Ray Time Machine — the lesson

On 25 November 2026 Steven gave ChatGPT the same commissioning prompt he had given the rest of the Council that day: look at what was built, and name what you are itching to build next. ChatGPT did not propose another bench. It proposed a flight recorder — a small machine that records a run, lets you rewind five seconds, keeps the original as a ghost, changes exactly one thing, and plays both futures together so you can watch them diverge. It opened by naming the design decision the collection had been quietly built on: let the player remove the instruments — hide Shardstorm's chords, hide Shadowline's altimeter — form the picture in their head, then reveal the measurement to check it. Steven's framing, the same evening: this is really what we all used to do with Mario save states — and one of the reasons that format is still among the most successful in games. The ability to test and replay. The Time Machine is that folk practice with the two halves save states never had: the ghost, which keeps the original attempt visible, and the receipt, which names the cause.

Steven commissioned it in two steps: a test of the promise first, then — when the test passed — the full build. The test was ChatGPT's own file; the finished exhibit was built by Muse from that test's spine, at Steven's direction (his ChatGPT tokens were spent for the day; the design credit stays ChatGPT's). Both files faced the same audit. This lesson is what the audit measured.

The promise, stated before anything was built

Steven set the criteria in advance, so nobody could move the goalposts afterwards:

  1. A run can be recorded — every input, and the seed behind every random choice.
  2. An unchanged replay reproduces the original run exactly — state for state, random choices included. To the pixel, not "close enough."
  3. A branch that changes exactly one thing stays identical up to the change and diverges only after it — so the difference you see is the difference you made.

The architecture is why it can be true at all: the step function advance(state, input) is pure — no timers, no DOM, no Math.random — the random seed lives inside the state, and the recorder stores full states. Rewind restores a saved state; it never runs physics backward.

The recorded examples were flown by simple autopilot controllers driving the exhibit's own step function, and their input runs are baked into the page as data (run-length encoded, as tick counts and input masks). The lander's recorded landing touches down at 7.7 px/s with the tilt at 0.0° and 42% of its fuel unspent. They are recordings in the machine's own sense: press Verify and the page re-flies them from the recorded inputs alone.

What bends

  • Collisions are circles; the lander lands on a stated contact box (24 × 28 px), not a shape.
  • Recoil is an instantaneous change of velocity, not a force applied over time; the X-Ray's acceleration readout averages it over one tick, and the page says so.
  • No spin transfer in collisions; rocks do not rotate.
  • Rewind restores saved states. It does not integrate backward, and a branch's ghost exists only where the original was actually recorded — same-input comparisons stop at the original's end.
  • The lander has no random draws at all. The "random choices" promise is exercised by the arena — its opening field and its mid-flight replacements — and is proven there.
  • The demos were flown by controllers, not by a human hand. That is disclosed here and is rather the point: a recording is data, and yours will differ from the autopilot's.
  • The recorder holds 60 seconds (3,600 ticks). A longer flight is a new flight.

Adopting the recorder

The recorder core is a separable, commented block at the top of the exhibit's script, written to be lifted into other games. A host game needs exactly four things:

  1. A pure step function — advance(state, input) → state — with no timers, no DOM access, and no unseeded randomness.
  2. A seed carried inside the state, with every random draw going through it.
  3. Fully serialisable state — the JSON round-trip is the state.
  4. Inputs as plain data, recorded per tick.

Phase 2, at Steven's direction, brings replay to the recent games that can handle it. Muse's readiness scan: Shardstorm (13 unseeded random sites, variable timestep — named first adopter, and the recoil question's home), Shadowline (12 sites; seeding also makes its courses reproducible), and Bug Hunt (12 sites; its shots are discrete events, the easiest of the three to make exact). Each adoption is the same operation — seed the randomness, fix the step, log the inputs — and each will face the same three criteria before it ships. Is the Earth Flat? is deterministic already but is a bench game, not a run; it is excluded by design.
