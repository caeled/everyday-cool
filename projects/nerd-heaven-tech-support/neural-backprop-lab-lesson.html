Neural Backprop Lab — the lesson

A neural network learns by being wrong, measurably, and then apportioning the blame. It makes a prediction, a loss function scores how wrong the prediction was, and backpropagation carries that error backwards through the network, using the chain rule to work out how much each individual weight contributed — the gradient, ∂L/∂w, for every weight in the net. An optimiser then nudges each weight a small step against its gradient, and the network tries again, thousands of times. This playground trains real networks in the browser on spirals, rings, moons and the classic XOR problem. This page is the other half of the lab: the concept and the math, and the audit that checked the shipped gradients against finite differences — the numerical equivalent of nudging each weight by hand and watching the loss move — and then drove every training claim the page makes.

Verdict: PASS-grade — gradients exact against finite differences (≤1.5×10⁻¹⁰ across 295 parameters), Adam textbook with bias correction, and every training claim driven true: XOR, Spirals, Rings and Moons solve at the page's presets, 0-hidden-layer XOR plateaus at 62%, and the overfitting demo's train/test gap is real; the bends are labelling-grade only.

The concept

Forward pass, loss, backward pass

Data flows forward: inputs are multiplied by weights, summed, and passed through a non-linear activation function — tanh, ReLU, sigmoid or Swish — layer by layer until the output layer produces a prediction. The loss compares that prediction with the true label; this lab uses binary cross-entropy, which punishes a confident wrong answer far harder than a hesitant one. Then the flow reverses. Starting from the output error, backpropagation applies the chain rule layer by layer, producing for every weight the gradient ∂L/∂w: how much the loss would rise if that weight rose a little. The lab's Backpropagation Inspector and its slow-motion Backprop Wave visualise exactly that backward pass.

Why XOR is the honest test

XOR — output 1 when exactly one input is 1 — cannot be separated by a straight line, so a single perceptron with no hidden layer cannot learn it, at all, however long it trains. Add one hidden layer and the network can bend its decision boundary around the problem. It is the smallest complete demonstration of why depth matters, and the lab teaches it — so the audit ran it both ways, with and without the hidden layer, on the page's own data.

Optimisers, learning rate, and overfitting

Plain SGD steps each weight by learning-rate × gradient. Adam keeps running averages of the gradient and its square and scales each weight's step by them, with a bias correction for the early steps when those averages are still warming up. The learning rate sets the step size: too small and training crawls, too large and it can bounce apart. Train long enough on a small dataset and a network will memorise it — training loss keeps falling while performance on unseen data gets worse. That is overfitting, and L2 regularisation (a penalty λ on large weights) is the standard brake: the lab has a dedicated overfitting preset, and the audit drove that too.

The concept/math

The output delta: BCE loss meets a sigmoid output

δoutput = dL/dz = p − t With binary cross-entropy loss and a sigmoid output unit, the derivative collapses to prediction minus target — no fractions, no leftover sigmoid terms. The shipped code uses exactly this. Hidden-layer deltas then multiply the back-carried error by the true activation derivative; the audit checked the Swish derivative in the code, written a + s(1−a), and confirmed it is algebraically identical to the true s + a(1−s).

Adam, as written in the paper

m̂ = m / (1 − β₁t)  ·  v̂ = v / (1 − β₂t)  ·  w ← w − lr · m̂ / (√v̂ + ε) β₁ = 0.9, β₂ = 0.999, ε = 10⁻⁸ — textbook Adam with bias correction, implemented as written in Kingma & Ba. The hats are the bias correction: without them the moment estimates start biased toward zero and the first steps are wrong-sized.

How the audit checks a gradient

∂L/∂w ≈ [ L(w + ε) − L(w − ε) ] / 2ε,   ε = 10⁻⁶ Central finite differences: nudge the weight up, measure the loss; nudge it down, measure again; the slope between the two is the gradient, computed without any calculus at all. Do that for all 295 parameters across six architectures and compare against the analytic gradients the shipped backprop produces. If backprop has a bug, this finds it.

What bends — labelling-grade only

The Inspector's ∂L/∂w is not the pure gradient: the Backpropagation Inspector reads lastGradW — the gradient after the L2 term (λ·W) has been added and after the ±5 clamp. At the default λ = 0.0005 the distortion is tiny, but the number shown is not the pure ∂L/∂w its label states, and at the L2 = 0.025 quick-setting the regularisation contribution is material.

The output unit is always sigmoid, whatever the badge says: the activation badge (Tanh / ReLU / Sigmoid / Swish) describes the hidden layers only; the output unit is always a sigmoid rescaled to (−1, +1). That is standard practice for BCE — and it is nowhere disclosed on the page.

The stability at extreme learning rates is engineered, and unmentioned: gradients are clamped to ±5 in the update step and non-finite weights are reset to 0. That clamp is why the lr = 3.0 run above stays finite. True, and reasonable — the page just never says it is there.

Empty-data cosmetics: with a Custom dataset and no points painted (or after Clear), the HUD shows loss 0.000 and accuracy 0.0% rather than a blank or undefined state, and Step Epoch on empty data is a silent no-op. Cosmetic only — nothing crashes.

One honest limit on the audit itself: canvas paint input was dispatched without error but could not be meaningfully exercised under the headless DOM's zero layout — the one interaction not fully driven. Everything else on the page was.
