The Genesis Console — the lesson

Sega’s 16-bit machine — and the Sega CD door beside it. This is the audit record: what engine it runs, where the files came from, what the audit measured driving the shipped page, and what bends. One of the bends is a real defect, found by the re-audit, named in full below, and fixed in the finishing pass the same morning; the console’s own Help ▾ carries the playing instructions.

▶ Open The Genesis Console

Where this one came from

Steven, the morning after the Atari pair landed (25 November 2026): build both of the next two — the Vectrex, and this one. The Genesis shape was his: a cartridge slot, and a Sega CD door with a bring-your-own BIOS slot and a disc slot, because “there were lots of cool hack CDs for the Genesis” — the CD homebrew shelf is the draw. The build went in with the Vectrex in one pass; this lesson was completed by a second, independent audit pass that re-drove everything and found the first pass’s unfinished edges — including, plainly, in this lesson’s own audit section.

What Genesis Plus GX and EmulatorJS are

Genesis Plus GX is the core: Charles MacDonald’s Genesis Plus, carried forward by Eke-Eke — the core the emulation world trusts for this machine, and for Sega’s 8-bit machines besides (the same build also emulates the Master System and the Game Gear; those are future pages, not this one). It runs here under the EmulatorJS 4.2.3 frontend, the same frontend family as the SNES, DOS, 7800 and 5200 racks in this room. Both were copied into the emulatorjs-genesis/ folder beside the console page ahead of time, byte-for-byte, so the console plays with no network at all.

The license question, in plain words

The frontend is GPL version 3, like its shelf-mates. The core is not the GPL — Genesis Plus GX is released under its own license, carried verbatim in the rack as LICENSE-genesis-plus-gx.txt (fetched from the core’s own repository, because the npm package names a license file it does not ship). Its shape: redistribution is permitted only non-commercially — the code “may not be sold, nor may it be used in a commercial product or activity” — with the copyright notices reproduced. Everyday Cool is a personal, non-commercial shelf, which is the use the license contemplates, and the notices ride along in the rack. The Sega CD BIOS is Sega’s firmware and is not in the rack, not bundled, and never downloaded: it is bring-your-own, like the 5200’s.

The threading verdict — this one runs on the plain site

Genesis Plus GX is not in the frontend’s requires-threads list (that list is exactly ppsspp and dosbox_pure), so the page sets no threading flag and needs no cross-origin isolation. Measured, not inferred: on a plain local server with crossOriginIsolated === false, the frontend fetched the legacy (non-threaded) core payload and the machine ran at a full 60 frames per second (frame counter 185 → 305 → 396 across 3.5 measured seconds). Served again with isolation headers (crossOriginIsolated === true), it ran the threaded build instead. Either geography works; the plain site gets the legacy build, like the 7800 and 5200.

The audit — a homebrew test cartridge, driven through the shipped page

The audit cartridge is the inputtest from Stoatworks’ AV Test ROMs — original homebrew under the MIT license, built for exactly this job: it draws the pad on screen and lights each control as the machine sees it, with the raw port word in hex beside it. Audit-only; it is not in the rack and never ships. Driven through the shipped page’s own slot, Start button, and state panel:

  • Boot: the cartridge booted to its rendered title screen in about two seconds; the screen runs at 640×448 (the machine’s 320×224, doubled).
  • State codes: Export wrote a GENSTATE1: code of 1,381,762 characters — 1,036,312 bytes of machine — and Import answered “State restored. The machine is exactly where the last player left it.” The round trip works. (Note the size: the console page’s own Help guesses “tens of kilobytes” for Genesis states. The measured truth is just over a megabyte — plan your paste accordingly.)
  • The network: the page and the rack ask for nothing outside this room — with one exception, logged honestly: the vendored frontend makes its own built-in update check to cdn.emulatorjs.org when it starts. It changes nothing and the console plays the same with it refused, but it is a phone-home the other racks’ frontends share, and it is named here rather than smoothed over.
  • The pad — the finding of this audit: the cartridge’s pad never answered. Real key events, synthetic key events on the very element the frontend listens to, and direct calls into the emulator’s input function — held, repeated, on both core builds, at a measured 60 fps — never lit a single control; the test screen sat at UNSEEN through every drive. The audit cannot honestly print a key table “measured at the cartridge,” and the console page’s Help — written by the first pass — claims exactly that measurement over a table that was left an empty placeholder. Both halves of that were corrected in the finishing pass — the page’s Help now carries the control map read from the running frontend, under a preamble that says exactly that — and the first cartridge Steven loads, played with his own hands, is the receipt that settles what the sandbox could not.

The control scheme — a real defect, and the one-line fix

Digging under the pad failure found a defect that is not a sandbox question — it is in the frontend’s own arithmetic, measured live from the running page. The frontend picks a control scheme for the core from a lookup table, first match wins, and genesis_plus_gx appears in that table under segaMS (Master System) before it appears under segaMD. The console page never overrides the choice, so the frontend builds the pad as a Master System pad: two buttons and a stick. Measured from the shipped page’s own running controls table, that is all a visitor gets:

KeyThe pad, as shipped
Arrow keysThe stick
XButton 1
ZButton 2

No Start, no A, no C, no X/Y/Z, no Mode — most Genesis games cannot be played past their menus like that. The fix is one line the page did not set: window.EJS_controlScheme = "segaMD". With that line injected, the same audit measured the frontend’s full Genesis table, which is the map the console now carries:

KeyThe pad (Genesis scheme)
Arrow keysThe stick
S / X / ZA / B / C
A / Q / EY / X / Z (six-button row)
EnterStart
VMode

Why this fix did not wait for a sanction: the console page is this project’s own build, not a guest file shipped byte-for-byte — the placeholder and the wrong size line were this pass’s own unfinished work. The finishing pass applied all three the same morning the audit found them: the scheme line in the page’s launch(), the key table filled with the measured Genesis map above, and the state-size line corrected to the measured 1,381,762 characters. What remains genuinely open is the cartridge-level press test, which no sandbox drive could land — that receipt belongs to the first player.

The Sega CD door

The door’s mechanics were driven as far as a sandbox honestly can. The disc slot takes .iso, .cue and .chd images (or a .zip holding a cue sheet and its bin); the BIOS slot takes your own .bin and a region pick — US, Europe, Japan — and the page wraps the bytes, unchanged, under the exact filename the core looks for (bios_CD_U.bin / bios_CD_E.bin / bios_CD_J.bin). With a disc in the tray and the BIOS slot empty, pressing Start on the door produced the refusal, verbatim:

“The Sega CD can’t wake up without its BIOS. The disc is in the tray, but the BIOS slot is empty — and that firmware isn’t bundled with the page, by design: it’s Sega’s. Your own copy (usually 131,072 or 262,144 bytes) goes in the CD BIOS slot, and then the door will open.”— and the door’s note: “Still waiting on the BIOS — it goes in the CD BIOS slot, above the disc slot.” The machine stayed dark, and nothing left the machine.

A real CD boot needs a lawful BIOS and a disc; there is no freely-distributable pair to audit with, so the first disc through the door is Steven’s first-disc receipt — his own BIOS, his own CD image (the homebrew CDs he named are exactly what the door was built for).

Honest notes

The pad bend, stated whole: as shipped, the console’s pad is the wrong pad (two buttons, no Start) because of the scheme lookup above, and the audit’s sandbox drives could not make any pad input reach the cartridge even with the right scheme in place. What is proven: the machine boots, renders, runs at speed, and freezes/restores its whole state. What is not: that the keys play — yet. The one-line fix and Steven’s first cartridge settle it.

State codes are married to this core build — a code made here loads here, against the same cartridge; the page’s panel says the same.

Same core, more machines: this build also emulates the Master System and the Game Gear — deliberately not wired into this page. If they come, they get their own cabinets and their own audits.

No BIOS for cartridges: a Genesis cartridge needs none — the boot code is the machine’s own. Only the CD door asks for firmware.
