What you are looking at

One stack, built live: transistor → gate → adder → memory → CPU → GPU wing. Every stage on this page is driven by the same pure core fenced at the bottom of the file. Nothing is a hardcoded truth table: gate outputs are computed by evaluating a transistor network, the adder is built from those gates, the CPU's ADD literally calls the adder, and its registers are the latch stage's latches.

Stage (a) — The Switch

A transistor is modelled as an ideal switch: base = 1 → the collector path conducts; base = 0 → it does not. A NOT gate is one transistor pulling the output to 0 when its base is high (a pull-up holds it at 1 otherwise). A NAND gate is two transistors in series in that pull-down path: the output falls only when both conduct. Series conduction is the AND of the conduction states — that AND is evaluated, not looked up.

Stage (b) — Gates from transistors

NAND comes straight from stage (a)'s network. AND = NAND followed by NOT. OR = NAND of the inverted inputs (De Morgan). XOR = the classic four-NAND composition. Every composition is evaluated through the core's gate functions, which are built on the transistor-network NAND.

Stage (c) — The Adder

A 1-bit full adder from XOR/AND/OR gates: sum = A ⊕ B ⊕ Cin, carry = (A·B) + ((A⊕B)·Cin). The 4-bit adder chains four full adders, carry rippling bit to bit. It takes a carry-in (0 in the panel; the proofs exercise both values). Sibling bench: Wire the Adder in Everyday Computing, where you wire this same adder by hand.

Stage (d) — Memory

An SR latch is two NAND gates cross-coupled — each gate's output feeds the other's input — so the circuit remembers. The core models it with state plus iterative settling: it re-evaluates the two NANDs until the outputs stop changing. Set / Reset / Hold are demonstrated, and a 4-bit register is four such latches with a Write button.

Stage (e) — The CPU

A tiny 4-bit accumulator machine. Memory is 16 nibbles. An instruction is two nibbles: opcode + operand, so the program counter advances by 2. Opcodes: 0 HLT, 1 LDA, 2 STA, 3 ADD, 4 SUB, 5 JMP, 6 JZ, 7 OUT. ADD calls the stage-(c) ripple adder; SUB is that same adder fed the inverted operand with carry-in 1 (two's complement). Arithmetic is mod 16: 15 + 1 = 0 with carry out — the wraparound is named, not hidden. The demo program adds 1+2+3+4+5 = 15, exact in 4 bits. Registers are stage-(d) latch registers.

Stage (f) — The GPU Wing

A 16×16 grid of brightness nibbles (0–15). One operation — invert (15 − v) — is applied two ways: serially, one pixel per modelled step (256 steps), and by 16 parallel lanes, one row per lane per modelled step (16 steps). Honest framing: your browser still executes both versions serially underneath. What is modelled is the organisation — same operation, many data — and the step accounting of that model. The proof is that both organisations produce element-identical output.

Simplifications, stated

Transistors are ideal switches (no threshold voltage, no leakage, no analogue region). Latch settling is iterated evaluation, not continuous-time feedback. Arithmetic is mod-16. GPU parallelism is a model of organisation and step counting, not real hardware concurrency in your browser. Full bends list is on the lesson page.
