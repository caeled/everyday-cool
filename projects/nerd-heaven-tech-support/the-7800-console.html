The 7800 Console — how it works

This page is a working Atari 7800 ProSystem, emulated in your browser. The engine is ProSystem — the Atari 7800 emulator by Brian Berlin and Greg Stanton, carried into a libretro core — running inside the EmulatorJS frontend (GPL-3.0). Both are embedded unmodified; their licenses ride with this page (see the lesson for the receipts). What the page deliberately does not contain is a single game: you bring the cartridge.

The machine

  • The 7800 (1986) is the 2600's bigger sibling: a 6502-family machine (the SALLY chip) with the MARIA graphics chip doing the heavy lifting, and the old TIA still aboard — which is why the real hardware plays nearly the whole 2600 library too. This core runs the machine in its 7800 mode; your 2600 cartridges have their own console two doors down.
  • No BIOS is needed. Unlike the 5200 beside it, this machine wakes up on the cartridge alone.
  • Your cartridge is read locally from the file you pick — from a mapped network drive, a USB stick, wherever it lives. Nothing is uploaded, ever.

The cartridge slot

  • The slot takes a .a78 file (a ROM image with its 128-byte header — the standard shape of the 7800 library), a raw .bin, or a .zip holding one of those. Pick it, then press Start the machine. To change games, reload the page.
  • Homebrew and demo cartridges in .a78 form are first-class citizens here — the 7800 has one of the liveliest homebrew scenes of any machine on this shelf.

Playing

  • Click the screen first — the machine reads keys only while it has focus. If the keys stop answering, click the game picture again.
  • The key table printed under the screen was measured at the cartridge on this very page — read the lesson for how, and for the one switch the keyboard can't reach.
  • A gamepad works too, and two players share the one keyboard the way they shared one couch.

Where this console can live

  • This core ships a non-threaded build, so it needs no cross-origin isolation: it runs right here on the ordinary website, and anywhere else this folder is served, including your Baton Box.
  • It does not run as a lone saved file (file://): the frontend fetches its core with requests a browser refuses from a bare file. If you opened this page that way, the console says so below instead of failing silently. Open it from the site, or serve the folder — the Baton Box serves it happily.
  • Once it has started, everything is local: the emulator is served from this site, your cartridge is read on your machine, and the machine makes no network requests of its own.

Window size, fullscreen, pop out

  • Standard / Large / Extra large resize the cabinet window; the emulator follows the box. Fullscreen gives the machine the whole display. Pop out lifts the running machine into a full-window view of its own — the same session, still running, nothing restarted — and Pop back in (or the Esc key) sets it back into the page.

The fine print

  • No games are included, hosted, or downloaded by this page — by design, and permanently. Your library is read from your machine only.
  • ProSystem rides under GPL-2.0 and the EmulatorJS frontend under GPL-3.0; both license texts sit in the emulatorjs-7800/ folder beside this page.

On a touch screen: the emulator draws its own on-screen gamepad — if it is not showing, tap the controller button at the edge of the player.

🗂️ Which file?

The 7800 library travels as .a78 — a ROM image wearing a small header that tells the machine its shape. Raw .bin dumps work too; the core reads the size and maps it the way the real slot did. If your cartridge is still zipped, hand over the zip — the machine opens it itself.

The start button lights when a cartridge is in the slot.

📚 Or borrow from the public shelf

These cartridges live at the Internet Archive — a public library of software — and are served by the Archive, from the Archive. We host no games here; this page only opens the door. Your own library never leaves your machine, and nothing you borrow is kept here either.

Why a door, and not the slot? The Archive's file shelves don't currently let other pages take books down — their servers send no permission header, and browsers enforce that absolutely — so a shelf cartridge can't be loaded into this console directly today. Press a title and it opens on the Archive's own page, where the Archive's own player runs it in their house. The day the Archive opens that header, these same buttons will load the game right here.

🏃 The challenge baton

Freeze the machine mid-game and hand the moment to the next player as a State Code — one block of text. They load the same cartridge, paste the code into Import, and the machine resumes where you left it. Honest warnings, measured in the lesson: state size varies by game, and every code is core-build-fragile — married to this exact core build, so codes travel between players on this console, not between different emulators.
