The Apple IIe Console — the lesson

Why this machine is here, what was measured before it shipped, and what bends. Every number below was driven, not read off a brochure.

Why a whole computer?

The 6502 Bench, two shelves down, is a bare chip on purpose: registers, RAM, a screen — the machine an assembly programmer actually talks to. But Steven's request that started this build was a game, The Oregon Trail, and a game like that doesn't run on a chip. It boots a whole computer: a Disk II controller reading a DOS 3.3 disk, Applesoft BASIC in ROM, 128K of banked memory. The Bench can't do that and was never meant to. So the emulator shelf gained the missing rung: not a chip this time — the computer itself.

A gate ran first, before any building: candidate browser Apple II emulators were tested against four prongs — a license that ships with attribution, an authoritative build, a real boot of the actual Oregon Trail disk, and fully offline operation once vendored. Apple2TS passed all four. Steven approved the build on 2026-11-24, having seen the caveat in the next section first.

The caveat, in the open

An Apple II cannot boot without Apple's firmware ROMs, and every browser Apple II — this one included — bundles those ROM images inside its build. The MIT license covers the emulator code, which is Chris Torrence's and the contributors' to give. The ROM images ride inside the unmodified upstream build the way upstream ships them — the same posture as the project's own public site, and in spirit the same terms Steven already accepted for the SNES console next door (Snes9x's personal-use license). Nothing about it is hidden: shipping the unmodified build ships them, and this page says so on the record. The disks are a different matter — those are software, they stay the visitor's, and none are bundled here.

The machine, pinned

Apple2TS 3.8.0 by Chris Torrence and the Apple2TS contributors (github.com/ct6502/apple2ts), MIT license, vendored unmodified from the project's own GitHub Pages build, branch gh-pages at commit 718738e098f91691c3facbc3996e51284d6f3078. The vendored tree was diffed byte-for-byte against a fresh extraction of that commit: identical, except the two house files named below. One deliberate subtraction: upstream's bundled disk library (disks/, 60 files — disk images, covers, notes) was pruned, the same rule the NES console applied to JSNES's bundled ROMs. Ship the machine, never the software.

The also-rans, for the record: EmulatorJS carries no Apple II core at all. The Internet Archive's own player (Emularity + MAME) requires Apple's firmware set supplied separately and streams its parts from archive.org — the opposite of a vendored, silent rack. AppleIIjs (Will Scullin, MIT) is a credible fallback and was not driven this pass.

The Archive door, and the wall behind it

The console's Oregon Trail button does not fetch the disk, and this lesson shows why. The Archive's metadata API is wide open (Access-Control-Allow-Origin: *, verified with an Origin header), so the button resolves the item and confirms the disk is there. But the file servers send no CORS header at all — the download endpoint answers 302 with no Access-Control-Allow-Origin on either hop — so a web page is refused the bytes. That is the same wall the other consoles' public shelves stand behind, measured the same way.

The gate asked one more question: does Apple2TS's own built-in Internet Archive browser work unmodified from our origin? The honest answer, verified at the level the sandbox allows: it works the way its maker designed it — the catalogue search rides the CORS-open API, and the disk bytes ride a third-party CORS proxy (the emulator's own info panel credits “CORS Proxy by Corsfix”). The audit sandbox's browser cannot reach the public internet, so the panel was verified at header and bundle level rather than driven end-to-end — and our door doesn't use it regardless. Reading a disk for you through a stranger's proxy is a different posture from opening the Archive's own house, and the consoles here hold one posture: served by the Archive, from the Archive; hosted here, never. The one-click version of the button lights up when the page is served by the visitor's own Baton Box, which can fetch on the home network where CORS doesn't apply. That is box work, deliberately not in this build.

What bends

  • Boot is a press, not an insertion. A hash-loaded disk inserts but the machine powers on before it lands and waits at BASIC; a slotted disk likewise sits in the drive until booted. (One slotted disk appeared to start on its own — startup timing, not a promise.) The page's Boot button, or Alt+B, is a normal step, and the furniture says so. A real IIe spins its drive at power-on; this machine waits to be told.
  • blob: URLs are refused. The first slot design handed the emulator a blob: address for the visitor's file; measured result: the loader never fetched it — its URL parser only speaks http(s) and its library names. The shipped slot instead hands the file to the machine's own loader, the same one its drive bays use. The visitor's experience is identical; the machinery is the machine's.
  • The welcome screen still points at the pruned shelf. The machine's start screen invites a click on its Disk Collections icon “to load a built-in disk or game” — but the built-in library was pruned by design, so that panel opens onto the Archive browser and visitor-added disks instead. Upstream is unmodified, so the sentence stays; the Help drawer tells visitors the shelf here is their own disks, and the page's slot is the front door.
  • Cloud buttons ride along. The machine's own menus carry Google Drive and OneDrive loaders — upstream furniture for visitors who keep disks there. They only ever act on a deliberate click; the local path's receipt is the request log: zero external requests. The Help drawer fences them in one sentence.
  • States are files, not codes. A whole 128K machine packs to roughly 0.4 MB — hand to hand, like the 2600 console's .jst files. A base64 code wrap would run ≈535,000 characters, inside the Baton Box's guidance on paper, but the page ships the file, matching the machine's own design; if the Box ever learns this passenger, the arithmetic is already done.
  • The audit browser is a slow room. The sandbox's headless Chromium throttles the machine to a fraction of full speed (its own readout swung between 0.5 and 1.0 MHz), keystrokes landed seconds late, once a keystroke arriving mid-boot dropped the machine to BASIC (the gate's rig saw the same artifact), and once keys sent after a state restore didn't land inside the wait. The same paths drove clean boots, menus, choices, typing, saves, and restores across five sessions — but as with every console on this shelf, the builder's audit is not the receipt. Steven's first disk is.
