The 5200 Console — how it works

This page is a working Atari 5200 SuperSystem, emulated in your browser. The engine is a5200 — the libretro Atari 5200 core built on the Atari800 codebase — running inside the EmulatorJS frontend (GPL-3.0). Both are embedded unmodified; their licenses ride with this page (see the lesson for the receipts). What the page deliberately does not contain is a single game — or the machine's firmware: you bring the cartridge, and you bring the BIOS.

The machine

  • The 5200 (1982) is an Atari 400 computer wearing a console's clothes: the same ANTIC, GTIA, and POKEY chips, a 6502-family heart — and controllers that were famously ahead of their time and famously fragile: an analog stick that doesn't spring back to centre, ringed by a twelve-key pad.
  • The BIOS is required. The real machine can't wake up without its 2 KB firmware ROM (5200.rom), and neither can this core. That firmware is Atari's, so it is not bundled with this page and never will be: your own copy goes in the BIOS slot, is read locally, and stays on your machine — the same bring-your-own rule as the cartridge, one level down.
  • Everything you pick is read locally — from a mapped network drive, a USB stick, wherever it lives. Nothing is uploaded, ever.

The two slots

  • The cartridge slot takes a .a52, a raw .bin, or a .zip holding one of those.
  • The BIOS slot takes the bare BIOS file itself — usually named 5200.rom, exactly 2,048 bytes — not a zip of it. Whatever yours is named, the page hands it to the machine under the name the machine looks for.
  • Fill both slots, then press Start the machine. With a cartridge but no BIOS, the machine will refuse — in plain words, below — because the real one would sit just as dark. To change games, reload the page.

Playing — and the analog bend, named

  • Click the screen first — the machine reads keys only while it has focus. If the keys stop answering, click the game picture again.
  • The key table printed under the screen was measured at the cartridge on this very page — read the lesson for how.
  • The bend: the real 5200 stick is an analog potentiometer stick — it reads how far, not just which way, and it famously doesn't centre itself. A keyboard is digital: full deflection or nothing. This core maps the keys onto the stick's travel, so games play stiffer than they did on the real stick — the ones that read the stick's middle distances most of all. That is the hardware's own argument with every digital controller since, not a defect in this page; the lesson names it in the open. A gamepad with a real analog stick comes closest to the original feel.

Where this console can live

  • This core ships a non-threaded build, so it needs no cross-origin isolation: it runs right here on the ordinary website, and anywhere else this folder is served, including your Baton Box.
  • It does not run as a lone saved file (file://): the frontend fetches its core with requests a browser refuses from a bare file. If you opened this page that way, the console says so below instead of failing silently. Open it from the site, or serve the folder — the Baton Box serves it happily.
  • Once it has started, everything is local: the emulator is served from this site, your cartridge and BIOS are read on your machine, and the machine makes no network requests of its own.

Window size, fullscreen, pop out

  • Standard / Large / Extra large resize the cabinet window; the emulator follows the box. Fullscreen gives the machine the whole display. Pop out lifts the running machine into a full-window view of its own — the same session, still running, nothing restarted — and Pop back in (or the Esc key) sets it back into the page.

The fine print

  • No games and no firmware are included, hosted, or downloaded by this page — by design, and permanently. Your library is read from your machine only.
  • a5200 rides under GPL-2.0 and the EmulatorJS frontend under GPL-3.0; both license texts sit in the emulatorjs-5200/ folder beside this page.

📚 Or borrow from the public shelf

These cartridges live at the Internet Archive — a public library of software — and are served by the Archive, from the Archive. We host no games here; this page only opens the door. Your own library never leaves your machine, and nothing you borrow is kept here either.

Why a door, and not the slot? The Archive's file shelves don't currently let other pages take books down — their servers send no permission header, and browsers enforce that absolutely — so a shelf cartridge can't be loaded into this console directly today. Press a title and it opens on the Archive's own page, where the Archive's own player runs it in their house. The day the Archive opens that header, these same buttons will load the game right here.

🏃 The challenge baton

Freeze the machine mid-game and hand the moment to the next player as a State Code — one block of text. They load the same cartridge (and their own BIOS), paste the code into Import, and the machine resumes where you left it. Honest warnings, measured in the lesson: state size varies by game, and every code is core-build-fragile — married to this exact core build, so codes travel between players on this console, not between different emulators.
