Corrected by Halves — the lesson

Corrected by Halves is five small games — a cable-bus fault hunt, a checksum tree, a TCP congestion game, a Hamming parity bank, and a bisection oscilloscope — built on one idea: don’t try to get it all done in one move; head the general direction, and correct by halves. The game was built by Gemini Neon (Google Antigravity) at Steven Powell’s direction, and it is integrated into this room unchanged — the file on this bench is byte-for-byte the file that was delivered. This page is the collection’s half of the bargain: an audit. Everything below was checked against the game’s own code — much of it by playing the shipped file headlessly, through its own buttons and canvas — and where the game’s in-page Field Guide says more than its code does, the last section of this page says exactly that, in the open.

The one idea in five costumes

The curator of this room has a stated method for problems, and it is not “follow the map precisely.” It is: head the general direction of the problem, see what looks right and what doesn’t, notice what applies here that might apply there, correct constantly — and you get there by halves instead of full moves. Go Thataway, over in the Map Room, is that philosophy as a walking game: pace and bearing, drift and fix, arrival by successive correction. Corrected by Halves is the same philosophy after it puts on a lab coat. Each of its five games hands you a bracket — a span of possibilities with the answer somewhere inside — and one move: split it, ask which half, throw the wrong half away.

The unit of that move is the bit. If the answer is equally likely to be any of N possibilities, your uncertainty is log2(N) bits, and a test that cleanly halves the possibilities earns exactly 1.00 of them. That is the whole economy of the game:

uncertainty = log2(possibilities)  ·  one clean halving = 1 bit 1,024 relays hold log2(1024) = 10 bits of uncertainty, so ten good halvings — never eleven, never fifty — close the case. Every game below is that sentence wearing a different costume: the halves are taken in a cable, in a hash tree, in a send rate, in memory addresses, and in a number line.

Keep one distinction in your pocket for the whole page. Some of the five games measure the bits — they compute log2(old span ÷ new span) after every move and will honestly show you a wasteful 0.15-bit probe. Others print “+1.00b” as a scored label for a good move. The receipts section of each game below says which is which.

1 · Line Fault — binary search on a cable bus

The real-world method. A signal trunk has one dead relay among N. You can tap any relay and learn one of three things: CLEAN (signal present — the fault is downstream), DEAD (no signal — the fault is upstream), or a direct hit. That is the oldest move in field troubleshooting — split the run, test the middle, keep the guilty half — and it is binary search with a multimeter. The game’s own probe messages say it in this room’s language: “Relay #512 is CLEAN → Fault is THATAWAY →.”

The math. The game computes par exactly the way the Field Guide prints it: par = ⌈log₂ N⌉. The tiers are 32, 128, and 1,024 relays, so par is 5, 7, and 10, and the probe budget is par + 3 (8, 10, 13). Nothing forces you to tap the midpoint — you may tap anywhere, and the game measures what your tap actually earned: gain = log₂(old span ÷ new span). A midpoint tap earns its 1.00 bit; a timid tap near an end earns a fraction and spends the same budget.

The receipts. The shipped file was played headlessly through its own number input and Probe button, with the fault planted at every position in turn — all 32, all 128, and all 1,024. Midpoint play isolated every fault, and the worst case was exactly par at all three tiers: 5 of 5, 7 of 7, 10 of 10. The Field Guide’s claim — “even 1,024 stations takes at most 10 probes” — is not a slogan; it is the measured worst case. (A sequential scan from relay #1 averages ~512 checks on the big trunk. Halving is not a little faster; it is a different kind of fast.) One grace note: you can also win by pure elimination — when the bracket narrows to a single relay, the game ends even if you never tapped that relay directly.

2 · Checksum Tree — CRC-8, bisected

The real-world method. A frame of 16 or 32 bytes arrived with one flipped bit (two, on the top tier). Re-checking every byte is the linear scan; checking ranges is the halving. The game builds a binary tree over the frame — 31 nodes for 16 leaves — where each node holds the CRC-8 of its byte range. Query a node: if its checksum matches the expected value, the whole subtree is innocent and locks out; if it mismatches, drill into it. When one half comes back clean under a parent already known dirty, the game deduces the sibling is dirty for free — and on the single-fault tiers, a dirty result clears the sibling subtree outright. At the leaf, you flip the one flipped bit back, and the repair is verified twice: the leaf’s CRC must match, and at the end every byte must equal the original frame.

The math, verified. The checksum is a genuine CRC-8 — not a toy hash wearing the name. The code’s crc8() is the bitwise algorithm with polynomial 0x07 (x⁸ + x² + x + 1) and initial value 0x00: the CRC-8/SMBUS (ATM HEC) polynomial. Run the game’s own function over the standard check string "123456789" and it returns 0xF4 — the published CRC-8/SMBUS check value. A CRC with more than one term detects every single-bit error, which is why the hunt can never be fooled by the one fault it plants; the generator still re-rolls (up to 50 attempts) until the corrupted frame’s root checksum differs from the original’s, which is the check that matters on the two-fault tier, where the two faults are deliberately planted in opposite halves so the root is the only node holding both.

The receipts. Playing the shipped tree through its canvas: a perfect descent — one query per level — wins tier 1 at 4 queries against par 4 and tier 2 at 5 against par 5. The descent is not the whole cost, though: opening a leaf is itself a query, so when the first leaf you open is the corrupt byte’s clean twin, the same flawless descent finishes at 5 against par 4. On tier 3, the fully-guaranteed line costs 8 against a par of 7; par is reachable when one fault is opened directly from its quarter instead of probed down to the pair. The star thresholds (full marks at par, a grace band of two more) quietly absorb the difference — but par here is a best-case line, not a guarantee, and this page would rather say so.

3 · TCP Halver — AIMD, with you as the control loop

The real-world method. TCP congestion control is halving applied to a rate. A sender keeps a congestion window (cwnd) — how much it will put on the wire per round trip. It probes upward while the path delivers, and when packets drop it concludes it has found the ceiling and backs off hard: additive increase going up, multiplicative decrease coming down — AIMD. The game turns that into bracket-keeping against a hidden capacity. Your window starts at 4. A round at or under capacity delivers (and pays a 1.35× bonus at 90% utilization or better — a game rule, not a TCP one); a round over capacity drops, pays only a fraction of capacity (25%, or 15% on the satellite tier), and tightens your bracket: the highest clean window and the lowest dropping window become the walls. The signature move is the emerald ½ BISECT button: once both walls exist, jump straight to the bracket’s midpoint. On the higher tiers the capacity itself re-rolls mid-transfer — the “route shift” — and the bracket resets, because the fact you corrected toward is gone.

The math. The tiers are a 128-packet link with a 1,200 KB quota in 42 seconds, a 160-packet backbone (1,750 KB, 48 s, two shifts), and a 256-packet satellite link (2,600 KB, 52 s, two shifts, harsher drop penalty). Rounds tick every 0.62 seconds; capacity is a single hidden integer rolled between 28% and 84% of the tier maximum. Doubling from 4 reaches any capacity in ⌈log₂(cap ÷ 4)⌉ rounds — that is the ×2 button’s job — and after the first drop, each bisection halves the bracket’s width, so the uncertainty about capacity falls by a bit per correction, exactly as it does on the cable. A worked line: clean at 64 (lower wall 64), drop at 128 (upper wall 128), BISECT to 96 — you are now hovering in the zone where the quota fills fastest and drops stay rare, which is precisely what the star thresholds reward (full marks: finish with ≥ 14 s to spare and ≤ 5 drops).

The receipts. This is the game where the Field Guide’s voice and the code part company, and the honest box below has the details. The short version: in this game nothing is automatic. The window never grows on its own between rounds, and a drop never halves it — the log urges “Hit ÷2 HALVE!” and waits for your finger. That is not a defect; it is the design. The game makes you be the control loop, and it grades what a control loop is graded on: quota delivered before the SLA timer, drops kept down.

4 · Parity Matrix — Hamming’s halving, done in space

The real-world method. Line Fault halves in time: one test, half the world gone, repeat. Hamming codes halve in space: store several parity bits, each covering exactly half the bank, arranged so that the pattern of failing checks is the address of the bad bit, written in binary. This is the error-correcting code inside ECC memory. The game’s banks are textbook Hamming layouts: positions 1–15 (tiers 1–2) or 1–31 (tier 3), with parity bits at positions 1, 2, 4, 8 (and 16), data in every other position, even parity throughout — plus one overall-parity cell at position 0, which makes the physical banks 16 and 32 cells: extended Hamming, the (16, 11) and (32, 26) codes.

The math. Check Pp XORs every position whose index has bit p set, including the parity bit itself. A single flipped bit at position e disturbs exactly the checks whose bit appears in e’s binary form — so the syndrome, the sum of the failing masks, equals e. The game’s own telemetry example is the whole trick: P8 + P2 + P1 failing means cell #11, because 8 + 2 + 1 = 11 = 1011₂. Each check contributes exactly one bit of the address, which is why the Field Guide’s claim holds precisely: 4 checks pinpoint 1 bit in 15; 5 checks pinpoint 1 bit in 31.

The receipts. Every position was planted and played against the shipped code: all 15 positions in the small bank and all 31 in the large one — in every trial the printed syndrome equalled the planted position exactly, and clicking that cell repaired the block. Tier 2 removes the training wheels: the syndrome bits are shown but not summed for you, and the candidate highlighting is off — you add the failing masks yourself. Checks are free and unlimited (there is even a Check All button); the rationed resource is wrong clicks — four mis-flips across the whole tier ends it. The game is not testing whether you can ration questions. It is testing whether you can read the address the halves spell.

5 · Zero Crossing — Bolzano’s bisection

The real-world method. A hidden curve crosses zero somewhere in [a, b], with f(a) < 0 < f(b). Bolzano’s theorem — the intermediate value theorem — is the guarantee: a continuous curve cannot get from negative to positive without crossing. Sample the midpoint, keep the half whose ends still straddle zero, and the bracket halves every probe, forever, with no assumptions about the curve’s shape. The game’s oscilloscope zooms as the bracket narrows, and its par is the honest count: par = ⌈log₂(span ÷ 2·tol)⌉ — 8 probes to pin a root in [0, 100] to ±0.25, 10 for ±0.05 on the cliff tier, 15 for ±0.02 across [0, 1000].

The math, verified. The hidden curves are built from a hyperbolic tangent centred on the root — tiers 1 and 3 add a small sine wobble that fades to zero at the root itself; the cliff tier uses a steep sigmoid (tanh compressed ~14×) plus a gentle linear tilt. The audit extracted the exact function from the shipped file and tested it on a 2,001-point grid across 105 combinations of tier, root position, and wobble phase: zero sign violations — f(x) is negative everywhere left of the root and positive everywhere right of it, and f(a) < 0 < f(b) always. That sign discipline, not the curve’s smoothness, is what bisection feeds on, and it is perfect here. Played through the oscilloscope, midpoint probing locked the root at or under par on every tier tried — 8/8, 10/10 on the cliff, 15/15 and 14/15 on the micro-zoom.

The receipts — and the cliff. At deal time the game genuinely simulates a naive secant solver — the giant-jump extrapolator — from the bracket endpoints, capped at 40 steps, and the debrief quotes its real step count. Run verbatim against the cliff, that solver hit its 40-step cap (the debrief’s “40+ (diverged!)”) for roots at 20% and 35% of the span, needed 36 steps for a root at 80%, 7 at 65% — and once, for a root dead centre at 50%, landed in a single step, because a symmetric cliff makes the first giant jump a perfect one. The Field Guide says the cliffs “fool giant-jump extrapolators.” Measured fairly: they fool them often, sometimes for the full 40 steps — and occasionally the giant jump gets lucky. Bisection’s promise is duller and better: it never gets lucky and never needs to.

How it’s built — the architecture as found

Corrected by Halves is a single HTML file — 117,915 bytes, one script block, no libraries, and no external references of any kind: no images, fonts, stylesheets, or scripts are fetched, and the only link in the file points back to this room’s index page. It would run off a USB stick in a Faraday cage. The sound effects are synthesized live with Web Audio oscillators — little oscillator chirps, slides, and a four-note win arpeggio — so there are no audio files either.

Five modules, one router

The script is one strict-mode closure. Inside it, each game is its own module object with the same six-part interface — title, sub, init, draw, onClick, onKey — and a router (MODE_MAP + startMode) swaps the active module and tier. All five games draw onto one shared 860×470 canvas (scaled for high-DPI displays, capped at 2×) that is repainted every animation frame; each module keeps its entire game state in one closure object, so a restart is just a fresh init. The shared furniture — telemetry panel, diagnostic log, spark chart of per-probe gains, debrief overlay — is written by helper functions every module calls, which is why five quite different games report their progress in the same voice.

The career, and what the aids cost

Progress persists in the browser’s local storage under the key corrected_by_halves_v1: an ops score and a star map. The star total on the game’s header is real arithmetic — 5 games × 3 tiers × 3 stars = 45 — and the operator ranks step up at 5 (Field Tech), 14 (Signal Ops), 24 (Bit Surgeon), and 36 (Binary Oracle) stars above the starting Apprentice. Stars keep your best result per tier; the score simply accumulates on every win, so it is a lifetime total rather than a best-run record. Two training aids carry a price in the other direction: Line Fault’s ruler and Zero Crossing’s midpoint guide each pay a ×1.25 score bonus when played switched off — the game pays you to take the training wheels off. And a note for auditors: this lesson’s receipts were produced by loading the shipped file headlessly and playing it through its own wiring — its Probe button, its canvas clicks, its Check All button — with planted faults, then reading its own debriefs back. The game graded the audit; the audit just held the pencil.

Simplifications, named

Stated plainly: this game was built by Gemini Neon (Google Antigravity) at Steven Powell’s direction and is integrated unchanged. Its in-page Field Guide is its own voice — enthusiastic, and mostly accurate. This box is where the collection’s audit differs from that voice, precisely and without mockery: Gemini built a real thing, and the job here is to say exactly what it is.

TCP’s automation is you. The Field Guide says congestion control “ramps up your send rate (×2 Slow Start or +1/+4 Additive Increase) until packets drop, then cuts the window in half (÷2).” In the code, nothing ramps and nothing cuts on its own: the window changes only when you press a button, and after a drop the game logs “Hit ÷2 HALVE!” and waits for your finger. The “+1/+4” figure matches nothing on the deck — the additive buttons are +2 and +8 — and it matches neither protocol named: real TCP Reno adds roughly one segment per round trip and halves its threshold on loss, while CUBIC grows on a cubic time curve and backs off by ×0.7, not ÷2. The ½ BISECT button, the 1.35× peak-utilization bonus, the fraction-of-capacity paid on drop rounds, and a link capacity that re-rolls mid-transfer are likewise game rules wearing TCP’s clothes. As a simulator of TCP’s arithmetic it is a simplification; as a game about being the control loop, it is the honest article.

There is no seed. The header offers “↻ New Seed” and the debrief offers “↻ Replay Seed,” but the word seed appears nowhere in the code: there is no seed value and no seeded generator — every deal is fresh Math.random(), and both buttons simply restart the current game with a new random deal. In particular, Replay Seed cannot replay the deal you just played; the puzzle you lost to is gone. (The collection’s other seeded games, like Pass It On, can replay a deal exactly — that is the difference a real seed makes.)

Checksum par is a best case, and the loss line is softer than it looks. Par counts the tree descent; opening the final leaf is itself a charged query, so a flawless descent lands on par or par + 1 depending on which twin leaf you open first (measured: 4 vs 5 on tier 1; the guaranteed tier-3 line is 8 against par 7). The game actually ends only when queries pass budget + 4 — 13, 15, and 17 queries on the three tiers — and that overrun check runs on internal-node queries. Nothing on screen states either number.

The repair bay shows its hand. When a corrupt leaf is selected, the deck prints the XOR difference between the received byte and the expected byte — the exact bit to flip is named before you flip it, and wrong flips cost nothing. Real repair never hands you the pristine byte to diff against; the tree hunt is the honest part of that game, and the last step is a guided one. Similarly, “Merkle” names the tree’s shape rather than its arithmetic: each node’s value is a CRC-8 recomputed over its raw byte range, not a hash of its children’s hashes, and the game holds the expected checksum for every node in advance, where real Merkle verification carries a trusted root and a proof path.

The overall parity cell is a bystander. Position 0’s overall-parity bit is computed, drawn, and labelled P0 — and never checked, never clickable, and never the flipped bit: errors are planted only in positions 1–15 / 1–31. In a real SECDED code that bit is what distinguishes a single error from a double one; this game plants no double errors for it to catch, so the syndrome does all the work alone.

“Monotonic” is the code comment’s word, not the curve’s. Zero Crossing’s steep tier is strictly monotonic, but tiers 1 and 3 are not: the sine wobble makes the curve locally decrease in its flat tails (largest measured dip ≈ 0.004, always far from the root). What holds perfectly — verified at every grid point tested — is the property bisection actually needs: one crossing, with the sign of f(x) always agreeing with which side of the root x is on. Two smaller flourishes in the same game: a probe landing within ±tol of the hidden root wins instantly, a check no real instrument can make (real instruments don’t know the root); and tier 3’s “50,000× Micro-Zoom” name is span ÷ tol, while the win triggers at bracket width 2·tol — a zoom of at least 25,000×, with your actual zoom printed in the debrief.

Not every “bit” on the telemetry is measured. Line Fault and Zero Crossing compute the real quantity — log₂ of the span shrink — per move. Checksum Tree and Parity Matrix print scored labels instead (1.00 for a useful query or a mask, 0.25 for a query whose parent wasn’t known, 0.6 for a clean leaf). For parity the label happens to be exactly right — each mask’s answer genuinely is one bit of the address — but in the tree the numbers are grades, not information.
