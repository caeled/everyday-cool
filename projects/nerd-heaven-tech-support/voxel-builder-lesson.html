Voxel Builder — the lesson

Flynn and David love a certain block-building game, so their dad asked for a studio where they could build the same way — place cubes, break cubes, fly through the result — and then do the thing the real game never offers: export the world as a web page. This page is the other half of that bench: what a voxel is, how the whole world fits in a box of 16,384 numbers, how the drawing skips almost everything, and the receipts from proving the machinery before it shipped.

What a voxel is

A picture on a screen is made of pixels — picture elements — tiny squares in a flat grid, each holding one colour. A voxel is the same idea one dimension up: a volume element, a tiny cube in a 3D grid, each holding one thing. On the Voxel Builder each voxel holds one number: 0 for air, 1 for grass, 2 for dirt, and so on through the ten blocks of the palette. That is the entire world. There is no castle stored anywhere — there are only numbers, some of which happen to be arranged castle-shaped.

The world is an array of numbers

The plot is 32 cubes wide, 32 cubes deep, and 16 cubes high. Multiply them and the world is 32 × 32 × 16 = 16,384 numbers, stored in one long row — a Uint8Array, one byte per cube. Finding cube (x, y, z) in the row is one line of arithmetic:

index = (y × 32 + z) × 32 + x Height first, then depth, then width — like reading a building floor by floor, each floor row by row. Every part of the bench — the drawing, the picking, the saving — finds its cubes with this same formula, so the parts can never disagree about where a block lives.

This is the third studio on the row, and all three teach the same secret in different clothes. The Web Page Workshop: the code is the page. The Dash Builder: the level is data. Here: the world is data — an array of numbers, and everything else is that array dressed up for a different job.

Everything else is the array wearing different clothes

  • The picture is the array drawn: for each non-zero number, draw a cube — but only the faces somebody could actually see (the next section counts them).
  • The share code is the array squeezed: long runs of the same number collapse into a count and the number, and the bytes are written as text. A fresh grass plot is two runs — 1,024 grass, then 15,360 air — so the whole untouched world packs into the twelve characters VX1.AAQBADwA. A built scene from the proofs below, tower and all, took 68.
  • The exported page is the array with a window around it: the same core code, the same renderer, and the array baked in as that share code, wrapped in one standalone file that flies the world and never phones home.
  • The autosave is the array parked in the browser's storage box between visits.

One array, four costumes. When Flynn or David exports a page, nothing is translated and nothing can be lost in translation — the file carries the numbers themselves.

Don't draw what nobody can see

A cube has 6 faces, so the lazy way to draw the world is 6 faces per block. The fresh plot alone would be 1,024 blocks × 6 = 6,144 faces — and most of them are pressed against a neighbouring block, where no eye can ever see them. So the mesh builder asks, for every face of every block: is the cube across this face solid? If yes, the face is skipped. This is hidden-face culling, and the savings are not subtle:

WorldFaces if drawn naivelyFaces actually drawn
The fresh grass plot (1,024 blocks)6,1442,176 — the tops, the underside, and the rim
A solid 3 × 3 × 3 cube (27 blocks)16254 — only the skin; the middle block draws nothing at all
A world filled solid, all 16,384 cubes98,3044,096 — the outer shell only; 96% of the drawing skipped

Glass gets one special rule, stated in the code and here: glass never hides a face (you can see through it, so the block behind it still draws its face), and two glass cubes side by side don't draw the face between them. Everything else follows the one rule — solid hides, air doesn't.

Pointing at a cube

When you click, the bench has to answer a hard little question: which cube is under the pointer, and which face of it? The answer is a raycast — a pretend laser fired from the camera through the pointer. The bench walks it cube by cube using the Amanatides & Woo traversal: at each step, whichever grid wall (x, y, or z) the ray reaches first is the cube it enters next. The first solid cube it enters is the one you pointed at, and the wall it came through is the face — whose outward direction, the normal, tells the builder exactly where the new block belongs: one step along the normal, into the empty cube against that face. The proof below fires the ray from known spots and checks the cube, the face, and the distance to the hundredth.

The fences

Three rules keep the world a world, and all three live in one small function every placement goes through: nothing below the ground floor (a click on the underside of the grass asks for y = −1 and is refused), nothing at or above the ceiling (on top of a block at y = 15 the target is y = 16, refused), and nothing into a cube that is already filled. Breaking has the matching shape: a block comes out only where a block actually is, which is what the raycast reports.

The honest box

A tribute, not the game: this bench is inspired by the block-building game Flynn and David love, and it borrows nothing from it — no textures, no artwork, no sounds, no name on the door. Every block is a flat colour painted by this page's own code. There is no survival, no crafting, no mining luck, no mobs. Building is the game.

Flying, not walking: Explore mode flies. There is no gravity, no falling, and no collision — you can pass through your own walls like a ghost, which the bench says on its face. Walking physics would be a different, bigger machine; this one chose the camera that lets a builder inspect a build from inside the walls.

The Glow Block is bright paint: this page's light is baked into the cube faces (tops full-bright, bottoms at 55%, the two side pairs at 80% and 65%), so there are no lamps and no shadows. The Glow Block is painted at full brightness on every face, which reads as glowing. It lights nothing around it.

What was proven, and what takes eyes: before this bench shipped, its core — world, raycast, mesher, serializer, exporter — was run headlessly in Node against the shipped file, and every proof in the table below passed there and re-runs live on the bench itself. The audit also checked the mesh geometrically: every face the builder emits has a triangle normal pointing exactly along one of the six axis directions, outward. What no script can receipt is the picture — the WebGL drawing happens on the visitor's graphics card, and the first real render is the one on the builder's own screen. That half of the receipt belongs to Flynn's and David's dad, opening the page.
