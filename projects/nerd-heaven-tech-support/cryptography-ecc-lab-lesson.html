Cipher — the lesson

Modern secrecy rests on a strange bargain: some sums are easy to do and almost impossible to undo. Add two points on an elliptic curve and you get a third point, by a rule a ruler can draw; multiply a point by a secret number k and anyone can check the result, but nobody can work backwards from the result to k. That one-way street — and its older cousins in Diffie–Hellman key exchange, RSA, and the SHA-256 hash — is what this lab lets you drag, slide, and mine. This page is the other half: the maths in plain language, and the audit that drove the shipped code headlessly and checked it against independent implementations.

Verdict: PASS — the ECC group law is exact (full 57×57 addition table identical to an independent implementation), ECDH agreement verified by driving the shipped point-add as both parties, DH and RSA exhaustive (461,320 cases, 0 failures), SHA-256 bit-exact, avalanche 50.39%; bends: the "Double-and-Add: O(log k)" label describes a method never executed (the code adds repeatedly; the points are still correct), "secp256k1 Form" is only the a=0,b=7 equation shape over tiny primes — not Bitcoin's curve, and Eve's brute-force ticker is rigged to skip the secret so it can never show a hit.

The concept

An elliptic curve is the set of points satisfying y² = x³ + ax + b. Draw a straight line through any two points on it and the line meets the curve at exactly one more point; reflect that point across the x-axis and you have defined addition. Repeat the addition and you have scalar multiplication, k·G — a public key made from a private key k. Do the same work modulo a prime p, in the finite field 𝔽p, and the smooth curve becomes a scattered lattice of points with the same addition rule and no geometry left to exploit. Diffie–Hellman uses the same trick in ordinary modular arithmetic: two parties exchange ga and gb in public and both arrive at gab, which an eavesdropper cannot rebuild without solving a discrete logarithm. RSA instead multiplies two primes, publishes the product, and keeps the factorisation as the trapdoor. SHA-256 is different again: not a trapdoor but a blender — a hash where flipping one input bit should flip about half the output bits.

The concept/math

Point addition: chord and tangent

y² = x³ + ax + b  ·  λ = (yQ − yP) / (xQ − xP)  ·  xR = λ² − xP − xQ For doubling, the chord becomes the tangent: λ = (3xP² + a) / (2yP). Adding a point to its mirror gives the point at infinity, 𝒪 — the group's identity. In 𝔽p every division is multiplication by a modular inverse. The curve is only a group when the discriminant Δ ≠ 0, which the exhibit checks on its face.

Key exchange and RSA

A = ga mod p  ·  B = gb mod p  ·  S = Ba = Ab = gab mod p  ·  c = me mod n,   m = cd mod n For RSA, n = p·q, φ(n) = (p−1)(q−1), and d is chosen so e·d ≡ 1 (mod φ) by the extended Euclidean algorithm. The exhibit's default key is the classic textbook example: p = 61, q = 53, n = 3233, φ = 3120, e = 17, d = 2753.

SHA-256 and the avalanche

SHA-256 : {0,1}* → {0,1}256  ·  one flipped input bit ⇒ ≈ 128 of 256 output bits flip The exhibit implements FIPS 180-4 by hand and mines proof-of-work by searching for a nonce whose digest starts with a run of zero hex digits — the same search, at toy difficulty, that secures a blockchain.

The audit — what was driven and measured

The audit extracted the pure-logic sections from the shipped file verbatim and executed them headlessly in Node, cross-checked against independent Python modular arithmetic and hashlib. Interactions were driven through the same code paths the buttons and sliders call: the field switch, all 4 primes × 4 curve presets, the full addition table, scalar trails, every DH preset and slider extreme, every RSA prime pair and offered exponent, SHA live inputs, the 1-bit flip, and the proof-of-work search. What bends

The "Double-and-Add: O(log k)" label: the method named is never executed. The shipped trail code computes k·G by repeated addition — G+G+G+… — and the hop animation steps through every integer multiple one at a time, while the binary-decomposition box ("k = 7 = (111)₂ = 4G + 2G + G") describes the faster method in words only. Every resulting point is numerically correct; the algorithm label is false.

"secp256k1 Form" is only a shape: the preset sets a = 0, b = 7 — over ℝ, or mod p ∈ {23…97}. The real secp256k1, Bitcoin's curve, lives over p = 2²⁵⁶ − 2³² − 977 with a fixed generator and order; none of that is present. The word "Form" and the sub-label "a = 0, b = 7" hedge it, but a learner could easily believe they are using the real curve.

Eve's brute-force ticker is rigged: the DH render loop explicitly skips the true secret (if (dh.eveTryIdx === dh.a) dh.eveTryIdx++), so the "Brute DLP" readout can never show a hit. With secrets capped at 120 even for p = 7919, the discrete log here is trivially searchable anyway — "Stuck on DLP!" is theatre at these sizes. The protocol maths itself is exact.

A softer bend: ECC over ℝ is presented beside 𝔽p with the same "private key k / public key k·G" language, but over ℝ there is no discrete-log hardness at all. The formula bar does say "Domain: ℝ²", and 𝔽p mode carries the ECDLP label — worth a learner's caution, not a correction.
