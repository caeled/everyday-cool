Entropy — the lesson

Compression is not a trick; it is a measurement. Every message carries a quantity Claude Shannon named entropy — the average surprise per symbol — and no lossless code can beat it, on average, by even a fraction of a bit. Huffman coding gets provably as close to that floor as any symbol-by-symbol code can. LZW takes a different road, learning repeated phrases as it goes. JPEG takes a third: it stops being lossless on purpose, throwing away the frequencies your eye barely registers. This lab runs all three side by side. This page is the other half: the maths in plain language, and the audit that drove the shipped code headlessly against independent implementations.

Verdict: PASS — Huffman provably optimal (H ≤ L < H+1, Kraft sum = 1), LZW bit accounting exact against a strict decoder-synchronised simulation, DCT textbook-exact (≤2.3e-13 vs NumPy), Q50 quantisation tables byte-identical to JPEG Annex K; bends: the "Est. JPEG Size" heuristic runs ~25–35% low against a real libjpeg encode, and the "max entropy" label on the noise preset is loose.

The concept

If a symbol is certain, it carries no news. If symbols are uneven — an e far more often than a z — most of the message is predictable, and predictable bits are wasted bits. Huffman coding spends short codes on frequent symbols and long codes on rare ones, building the tree from the frequencies themselves, and the result is optimal: no other prefix code for the same symbols averages fewer bits. LZW ignores symbol frequencies entirely and instead builds a dictionary of phrases it has already seen, so a substring that repeats costs one code instead of many letters — which is why it crushes DNA motifs and runs that Huffman cannot touch. JPEG works on pictures, not text: it cuts an image into 8×8 blocks, rewrites each block as a sum of cosine waves with the discrete cosine transform, then quantises — rounding the wave amplitudes coarsely, hardest on the fine detail — so most coefficients become zero and the zeros compress away. What you lose is chosen, not accidental.

The concept/math

Shannon entropy and the Huffman bound

H = −Σ p(x)·log₂ p(x)  ·  H ≤ L < H + 1  ·  Kraft: Σ 2−ℓᵢ = 1 H is the entropy in bits per symbol; L is the average Huffman code length. The bound says the optimal prefix code lands within one bit of the floor — and a complete prefix code, with no wasted leaves, has a Kraft sum of exactly 1. Efficiency on the exhibit's meter is H/L.

LZW: a dictionary that learns

dictionary starts at 256 single bytes  ·  each new phrase takes the next code  ·  codes widen as the dictionary grows The encoder emits the longest phrase it already knows, then teaches itself that phrase plus one more character. The decoder rebuilds the same dictionary in lockstep from the codes alone — including the awkward KwKwK case, where a code arrives before its phrase has been entered. Bit totals therefore depend on exactly when the code width steps up, which is what the audit simulated.

The 8×8 DCT and JPEG quantisation

F(u,v) = ¼·α(u)α(v) · Σx,y f(x,y)·cos[(2x+1)uπ/16]·cos[(2y+1)vπ/16]  ·  quantised = round(F / Q(u,v)) JPEG first shifts pixel values by −128, transforms each 8×8 block, then divides by a quantisation table — the standard Annex K tables at quality 50, rescaled by the IJG rule at other qualities — and reads the survivors out in zig-zag order, low frequencies first. Quality 100 is the limiting case: every table entry becomes 1. PSNR, computed from the mean squared error against the original, is how the damage is reported.

The audit — what was driven and measured

The audit extracted the pure-logic sections from the shipped file verbatim and executed them headlessly in Node, cross-checked against a Python heapq Huffman, a strict LZW decoder-synchronised width simulation, and a NumPy direct double-sum orthonormal DCT-II. Interactions were driven through the same code paths the controls call: all Huffman presets and custom text (including empty, single-symbol, and Unicode inputs), encode/decode round-trips, all three DCT presets at qualities 10, 45, and 90, luma-only mode, and the top-K and quantisation paths. Canvas rendering itself was not executed. Total: 74/74 independent checks pass. No FALSE numeric claims were found.

What bends

"Est. JPEG Size" is a heuristic, not an encoder: it runs ~25–35% low against a real encode. It uses invented constants — a 640-bit header allowance, ~4 bits per non-zero coefficient plus a run-length fudge, chroma at 5.2 bits per non-zero. Cross-check: a real PIL/libjpeg encode of the same 64×64 portrait at quality 45 is 0.99 KB against the page's 0.73 KB estimate (1.36×). Right order of magnitude, and correctly labelled "Est." — but not comparable bit-for-bit with any real JPEG file.

"Max entropy incompressible" is loose wording: the noise preset's entropy is 6.21 b/sym — essentially maximal for its 74-symbol alphabet — yet the page's own Space Saved shows +21.6%, because the baseline is 8-bit ASCII and the alphabet is small. Every number on the page is honest; the word "incompressible" contradicts the meter next to it.

The single-symbol edge case sits exactly on the bound: for "AAAAAAAAAAAA" the page assigns code "0", so H = 0 but L = 1 = H+1 — outside the strict L < H+1 form. That is the standard degenerate exception for a one-symbol alphabet, and the round-trip still verifies.

"Keep Top K Zig-Zag" is a teaching addition, not JPEG: real JPEG has no top-K truncation. The control is labelled as its own slider and never claimed to be standard, but it silently compounds with quantisation in the PSNR and size figures.

Force-ON cell override fabricates a coefficient: toggling a dead DCT cell ON injects a dequantised value of 48.0 when the true coefficient is negligible (|raw| < 2), instead of restoring the true value. It is disclosed only as an override count in the block info — the reconstructed image then contains a wave that was never in the source.
