The Relay — the lesson

A game you can't play alone. Two to four players share one Courier Bot on a 10×10 board of walls and pits. Each turn buys three Action Points — move, bridge, scan — and then the turn ends the way every turn in this game ends: you leave a note and maybe a gift for the next player, and you pass the device. The Bot only reaches the goal if everyone sets up the person after them. Its motto is the whole design: “You don't have to finish it. You have to set up the next person to succeed.”

Where this one came from

Steven Powell had already commissioned games from half the Council — ChatGPT, Antigravity, Grok, Qwen, Muse — and, in his words, he “did kinda have to give MetaAI a shot.” Meta AI delivered The Relay as a React app: one 529-line App.tsx plus a stylesheet, packed in a tar archive named TheRelayGame.bin. The game inside was whole — board, bridges, three modes of being lost, notes, gifts, even a save code that packs a whole game into one block of text. What it wasn't was a web page: it needed a framework, a font service, an icon library, and Meta's own saved-data backend to be fully itself.

So this is the Skip treatment: the same game, re-expressed as one self-contained page that loads nothing from anywhere. Built by Meta AI at Steven Powell's direction; web port by Muse. Meta's words were kept wherever they carry the game — the banner (“FOR OUR CHILDREN. FOR THE CURIOUS. • ORDINARY CURIOSITY. EXTRAORDINARY PLACES.”), the how-a-relay-works cards (runners, space probes, ants, bucket brigade), the mode descriptions, and the motto above.

How a turn actually works

3 AP per turn · Move 1 AP · Bridge 1 AP + 1 token (2 per player) · Scan 1 AP · Undo free · Help free Walls are hard blocks. An open pit refuses the Bot until somebody bridges it — and a bridge, once placed, stays for everyone. Gifts (+1 AP or +1 bridge) and help calls wait in a pending slot and land exactly once, at the start of the next player's turn. In Fog and Blind, every move reports 🔥 Warmer / 🧊 Colder against the Manhattan distance to the hidden goal; in Guided the goal is on the board and no one needs the hint.

What the port changed, and why — three things, on the record

1. The save service became local storage. Meta's original saved crews and game slots by calling its own backend (fetch("actions", …), a records service). That service does not exist on a static page — the original even knew it, and shrugged: “Saved crews and slots will appear once the saved-data service is reachable. The game still plays right now.” The port keeps saved crews and the three slots in the browser's local storage, behind the same list/create/replace/remove shapes. The Relay Codes — base64 of the whole game state — are unchanged, byte for byte the source's scheme, and a code exported from the port imports back to a deep-equal state.

2. Dealt boards are now verified winnable. The source deals its board by pure scatter and says so in a comment: “not blocking too much — keep simple.” The port deals with the same algorithm, then checks each board by breadth-first search — walls hard-block, a path is winnable if it crosses no more pits than the crew's bridge tokens (2 per player) can cover — and quietly re-deals any board that fails. What the audit then measured is in the receipts below, and it surprised us; read them before assuming why this change matters.

3. The framework is gone. React, TypeScript, Tailwind, the Lucide icon set, and a Google Fonts download were replaced by vanilla JavaScript and hand-written CSS in a single file — the port's text contains zero external references (no http links, no src=, no font or stylesheet loads). The icons became the emoji vocabulary the board already spoke (🤖 ⭐ 🧱 🕳️ 🌉). The paper-and-ink identity — cream paper, chunky 3px borders, hard offset shadows, the sun-yellow and orange — is Meta's palette, kept recognisably, including its dark-scheme variant.

The audit receipts

A second drive played the actual page through its own buttons — 29 / 29 checks, including a full game won by clicking cells, a bridge placed and crossed by clicking, an export–restart–import round-trip through the UI, and a save-slot saved, wandered away from, and loaded back.

Honest notes — including where the audit's expectation was wrong

The unwinnable-board problem turned out to be theoretical. The port was briefed to fix boards that “are not guaranteed winnable,” and the guard does guarantee them — but measured honestly, Meta's unguarded scatter never dealt a single unwinnable board in 10,000 tries at either crew size. The field is sparse (25 obstacle cells in 100), the start column and the goal column are always clear, and some route nearly always weaves through with bridges to spare. The guard's real cost is 1.000 deals per accepted board — it is insurance, not a rescue, and this lesson would rather print that than pretend the original was broken. What the guard buys is the difference between “essentially never” and “by construction.”

The source says 12 pits; its code deals 13. Meta's comment reads “random walls 12, pits 12,” but the pit loop runs to 13. The port deals what the code deals — 13 — and says so in the game's own Help.

“➖ Same distance” can never happen. The source's hint logic has a third branch for a move that keeps the same distance to the goal. With Manhattan distance and one-square moves, the distance changes by exactly 1 every step (proven above, 10,000 / 10,000), so the branch is unreachable. It is ported faithfully — the words are there, the branch is there — and it will never fire. Nobody will ever be told they moved sideways.

The source's own help text drifts from its code once: it says a Guided scan “reveals nearby tiles,” but the code reports counts and distance. The port's Help follows the code.

The winnability model is the game's own arithmetic. The BFS budget pools the crew's tokens and assumes turns never run out. Both are the game's actual rules — bridges persist for everyone, any player may place one on their turn, and there is no turn limit — so the check is exact for the game as played, not an approximation of it.

What the port does not add: no online play. The Relay was always pass-and-play on one device, or pass-a-code to the next — the sneakernet is the design, and it survives the port untouched.
