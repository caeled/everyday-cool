The 6502 Bench — what this is

A working NMOS 6502 — the processor inside the Apple IIe, the Atari 800, the Commodore 64's cousins, the NES (as the 2A03), and the Atari 2600 (as the cut-down 6507) — built from scratch in this page, with 64 KB of RAM, a text screen, a keyboard, a printer, a two-pass assembler, and a small BASIC that lives beside the machine. Nothing here is a ROM image and nothing is emulated by someone else's code: the machine is the page's own, and it ships empty — you bring the software.

The memory map

AddressWhat lives there
$0000–$00FFZero page — the 6502's fast scratchpad. The examples keep pointers at $10–$12.
$0100–$01FFThe hardware stack.
$0300Where the FIB example parks its numbers.
$0400–$07BFThe text screen: 40 columns × 24 rows, one byte per cell, plain ASCII, written linearly left-to-right, top-to-bottom. (A real IIe interleaves its text page in a famously strange order; this bench chose the simple map and says so.)
$8000Default home for programs. The reset vector points here.
$8200Where the “Set up the next player” example leaves its half-finished routine.
$C000Keyboard data (read): the oldest queued key, with bit 7 set while a key waits — the Apple II convention.
$C010Keyboard strobe clear (read): removes the waiting key.
$C020Printer port (write): every byte written here is appended to the printer log on this page.
$FFFC–$FFFDReset vector. $FFFE–$FFFF: BRK/IRQ vector.

Running the machine

  • Run executes in fast chunks until the program parks itself (a JMP to its own address), hits an instruction budget of 2,000,000 (the polite way this bench says “endless loop”), or you press Stop.
  • Step runs one instruction; Step ×100 runs a hundred. The register readout follows every step.
  • The CPU X-Ray (Bench 1½, below the machine) watches the chip think: live registers and flag lamps, the last instruction taken apart — disassembly, effective address, cycles charged — a trace of the last 200 instructions, a memory watcher, a watch list, one breakpoint, and a slow gear. Every value is read from the real CPU; nothing is staged.
  • Reset restarts the CPU from the reset vector and keeps memory. Cold boot wipes all 64 KB, restores the vectors, and resets.
  • Programs end by parking: DONE: JMP DONE. That is this bench's halt.

The assembler

  • Two passes: forward labels are fine. Labels end with a colon: LOOP:. Comments start with ;.
  • Numbers: $FF hex, %1010 binary, 65 decimal, 'A' a character. Simple +/− expressions work, and <LABEL / >LABEL take a label's low / high byte.
  • Addressing is written the classic way: LDA #$10, LDA $10, LDA $1234,X, LDA ($10),Y, LDA ($10,X), JMP ($02FF), ASL A.
  • Directives: .org $8000 sets the assembly address; .byte 1, $FF, "TEXT", 0 emits bytes (strings allowed); .word LABEL, $1234 emits little-endian words.
  • One honest simplification: a bare number that fits in a byte assembles as zero page where the instruction has a zero-page form; a label always assembles as absolute (16-bit) unless you write <LABEL. No surprises in program size, ever.

The BASIC beside the machine

On real hardware, BASIC was a ROM — Applesoft on the IIe, Atari BASIC on a cartridge. This bench ships no ROM, so its BASIC is a small clean-room interpreter that lives beside the machine in the page, written for this bench. It speaks line-numbered BASIC: REM, LET, PRINT (; joins, , pads to the next 14-column zone), INPUT, IF … THEN, GOTO, GOSUB/RETURN, FOR/NEXT, END, with numbers, strings, + − * / MOD, comparisons, AND OR NOT, and the functions PEEK, ABS, INT, SGN, RND, LEN, ASC, CHR$, MID$, STR$, VAL. Variables are one or two characters (A, N2, A$). There are no arrays in v1 — the lesson says so too.

The bridge: POKE address, value writes straight into the machine's RAM and PEEK(address) reads it — so BASIC can write to the text screen at $0400 (decimal 1024) and the machine sees it. INPUT reads lines you queue in the input box before running.

The Drive Shelf — bring your own bins

  • The bench ships the machine, never software. The Drive Shelf loads your own .bin files: pick a file, choose the load address and the entry address, load, run.
  • Your library can live wherever you keep it — a folder on this machine, or a mapped network drive (say, Z:). Point the picker at it: a mounted share is just a folder, and the picker reads folders.
  • Nothing is uploaded anywhere. The file is read on this machine, in this page, into the machine's RAM, and that is the whole journey. Close the page and it is gone.
  • A .bin here is raw 6502 machine code — no header, no format. It lands at the load address byte for byte. If your bin expects a different home (an Atari cartridge image, a NES ROM with its header), that translation is future work; the lesson is honest about it.

Hand it on — Machine Codes and the Baton Box

Export Machine Code packs the whole machine — registers and all 64 KB of RAM — plus a note from you, into one block of text. Send it however you like; the next player pastes it into Import and the machine stands up exactly where you left it, your note on its screen's doorstep. The bench is also a registered passenger on the Baton Box, the little relay server in this collection: there, this same code is the state the box carries from player to player, and the box keeps the turn order.

Faithful quirks and honest limits

  • The JMP-indirect bug is reproduced on purpose. On a real NMOS 6502, JMP ($02FF) reads the target's high byte from $0200, not $0300 — the pointer does not carry into the next page. This bench does the same, because a bench that hides the famous bug teaches the wrong machine.
  • Decimal mode works (ADC/SBC adjust to BCD), with the NMOS flag quirk: N, Z and V come from the binary result before adjustment, exactly as the original silicon did.
  • Cycle counts are approximate — close, counted, and shown, but this is not a cycle-exact machine. There is no video timing, no Disk II controller, no speaker.
  • Unofficial opcodes stop the machine with a message. All 56 official instructions are here; the undocumented ones are not, in v1.
  • Self-check: the bench tests itself. Press Run the self-check at the bottom of the page, or open the console and run runProofs() — opcodes, the assembler, the examples, BASIC, the Drive Shelf path, and the Machine Code round-trip, all verified against the shipped code.

On a touch screen: the code box takes your tablet's on-screen keyboard and every button is tappable, so the Bench works — a real keyboard is simply faster.
