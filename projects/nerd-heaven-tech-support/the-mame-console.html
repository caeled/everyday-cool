The MAME Console — how it works

This page is a working arcade machine, emulated in your browser. The engine is MAME 2003-Plus — a libretro core built on the MAME 0.78 codebase, with years of backported fixes — running inside the EmulatorJS frontend (GPL-3.0). Both are embedded unmodified; their licenses ride with this page (see the lesson for the receipts). What the page deliberately does not contain is a single game. The console ships empty, the way the real boards did: you bring the romset.

The one rule of MAME: a core plays the set built for it

  • A MAME "game" is a romset: a .zip named by its shortname — pacman.zip, dkong.zip — holding exactly the ROM files its MAME version expects, down to the byte counts.
  • This console's core is MAME 0.78 vintage (2003), so it plays 0.78 / MAME 2003 romsets. Feed it a set built for a current MAME and the board will refuse it or run it wrong — that's not this page being broken, it's how MAME has always worked. The lesson carries a small diagnostic script that reads your archive's fingerprint sets and tells you its vintage before you blame the machine.
  • Your romset is read locally from the file you pick — from a mapped network drive, a USB stick, wherever it lives. Nothing is uploaded, ever.

The three slots

  • The game slot takes the romset zip itself. A plain, self-contained set (a "non-merged" set) needs nothing else: pick it, start the machine.
  • The parent slot is for clones. A clone set (say pacmid.zip) holds only the parts that differ from its parent (puckman.zip) and won't run alone. If your game is a clone, pick its parent zip here too.
  • The BIOS slot is for games that are children of a BIOS set rather than a game — the famous one is neogeo.zip (Neo Geo); pgm.zip (IGS) is another. If your archive keeps BIOS zips beside the games, this is where the right one goes.
  • Pick the game first, add a parent or BIOS only if your set needs one, then press Start the machine. To change games, reload the page.

The liturgy — clear the warning, coin, then start

  • First, the warning screen. A freshly booted board shows the core's copyright warning, and it eats coin and start presses until it's gone. Work the stick — left, then right on the arrow keys — to clear it, the way you would at a real cabinet that's just been switched on. (Measured on this page: until the warning clears, nothing else the keyboard says reaches the game.)
  • Then feed it. Click the screen so it has focus, hold V a beat to insert a coin, then hold Enter to start. Those are this frontend's coin and start keys, read off the shipped control map and proven at the cabinet in the audit — the lesson has the receipts.
  • About 5 and 1: on desktop MAME the canon is 5 for coin and 1 for start. In this stack a pad layer sits between the keyboard and the board, and those keys mean other things here (1 is the frontend's quick-save). If you'd rather have the desktop canon, the frontend's control settings (bottom toolbar) will remap coin and start onto any keys you like — your cabinet, your liturgy.
  • Joystick: the arrow keys. Buttons ride the frontend's pad mapping — Z, X, A, S are the button rows of most cabinets, with Q and E on the shoulders. Two players share the one keyboard the way they shared one cabinet panel; a gamepad works too.

Where this console can live

  • This core ships a non-threaded build, so — unlike the DOS Console — it needs no cross-origin isolation: it runs right here on the ordinary website, and anywhere else this folder is served, including your Baton Box.
  • It does not run as a lone saved file (file://): the frontend fetches its core with requests a browser refuses from a bare file. If you opened this page that way, the console says so below instead of failing silently. Open it from the site, or serve the folder — the Baton Box serves it happily.
  • Once it has started, everything is local: the emulator is served from this site, your romset is read on your machine, and the machine makes no network requests at all.

What sits this version out

  • CHD games — the ones that need a compressed hard-disk image (Killer Instinct, Area 51, Blitz, Gauntlet Legends) — are out. Those images run to hundreds of megabytes and this core's CHD support is era-limited besides. The page says so rather than letting a giant file fail mysteriously.
  • The 90s 3D era (Ridge Racer class hardware) is beyond a 2003 core. What this machine plays is the golden and silver age — roughly 1978 to 1994 — which is most of what the arcade ever was.
  • Samples: a handful of 0.78-era games (Donkey Kong's footsteps, Zaxxon) keep some sounds in a separate samples set. Without one, those games play with a few sounds missing — named here so silence isn't mistaken for breakage.
  • Vertical games (Pac-Man, Galaga) were drawn for a monitor turned on its side. They play here letterboxed in the horizontal screen — the frontend's settings can rotate the picture if you'd rather tip your head.

Window size, fullscreen, pop out

  • Standard / Large / Extra large resize the cabinet window; the emulator follows the box. Fullscreen gives the machine the whole display. Pop out lifts the running machine into a full-window view of its own — the same session, still running, nothing restarted — and Pop back in (or the Esc key) sets it back into the page.

The fine print

  • No games are included, hosted, or downloaded by this page — by design, and permanently. Your archive is read from your machine only.
  • “MAME” is a registered trademark of Gregory Ember; the name is used here descriptively, for a fan-made console page that runs your own romsets. MAME 2003-Plus rides under the classic MAME non-commercial license, carried verbatim beside this page; the lesson has the full story.
  • High scores and board settings live in the machine's memory for the session, the way they did when the cabinet was unplugged at night.

🏃 The challenge baton

Freeze the machine mid-game and hand the moment to the next player as a State Code — one block of text. They load the same romset, paste the code into Import, and the machine resumes where you left it. Honest warnings, measured in the lesson: state size varies by board (a small board's whole machine fits in a code shorter than this page's Help), some boards return no state at all — the Export will say so rather than hand you an empty code — and every code is core-build-fragile: married to this exact core build, so codes travel between players on this console, not between different emulators.
