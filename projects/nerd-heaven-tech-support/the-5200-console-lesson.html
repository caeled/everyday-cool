The 5200 Console — the lesson

Atari's 1982 SuperSystem — the big, strange, ambitious one, with the analog joystick that never centres and a telephone keypad on every controller — emulated in one page, and, like every machine on this shelf, it ships with no games at all. This console is also the shelf's one two-door machine: it needs your cartridge and your BIOS, the machine's own firmware, which is Atari's code and is therefore not bundled, not mirrored, and not in the rack — you bring your own copy, exactly as you bring the game. Under the hood is the a5200 core (built on the Atari800 lineage) inside the EmulatorJS frontend — both embedded unmodified, both licenses carried with the page. This page is the receipt: where they came from, why the BIOS stays yours, how the page hands it to the machine, and what was verified by driving the shipped page — refusal first, then a full boot through a real BIOS to a synthetic cartridge.

Where this one came from

The Atari 5200 SuperSystem (1982) was Atari's answer to the Intellivision and the coming ColecoVision: inside, it is close kin to the Atari 8-bit computers — a 6502 with the ANTIC and GTIA graphics chips and a POKEY handling sound, paddles and the keyboard matrix. Its controllers were the famous gamble: a true analog stick (potentiometers, not switches) that famously does not spring back to centre, two fire buttons, and a 12-key keypad with START, PAUSE and RESET riding on top. The machine boots from a 2 KB internal BIOS ROM — the firmware that draws the Atari logo, checks the cartridge, and hands over control. No BIOS, no boot: that was true on the real machine in 1982, and it is true in this page, on purpose.

The BIOS — bring your own, and the page's refusal

The 5200's BIOS is Atari's copyrighted firmware, so this collection's rule — ship the machine, never the software — applies to it exactly as it does to cartridges. The rack beside this page contains no BIOS file, and the audit's copy (obtained at audit time only, to prove the machine works) was deleted when the audit closed and was never in the tree. The page therefore has two slots, and its Start button tells the truth when only one is full. Driven in the audit, word for word:

“The 5200 can't wake up without its BIOS. The cartridge is in, but the BIOS slot is empty — and this machine's firmware isn't bundled with the page, by design: it's Atari's. Your own copy (usually 5200.rom, 2,048 bytes) goes in the BIOS slot, and then the machine will start.”The refusal, as printed by the shipped page when Start is pressed with an empty BIOS slot. The machine does not boot.

Pick a BIOS of any other size and the page says so, in the same plain words, and keeps the warning on screen: a real 5200 BIOS is exactly 2,048 bytes. (The audit's copy checks against the long-documented 5200 BIOS fingerprint, MD5 281f20ea4320404ec820fb7ec0693b38 — recorded here so the receipt is checkable, the file itself is not kept.)

How the page hands the BIOS to the machine

The hand-off has one non-obvious step, and it is documented here because the MAME Console's audit paid for the knowledge. The frontend delivers a BIOS into the core's system folder under the basename of the address it was given. Hand it a picked File directly and the boot hangs (the frontend's cache check calls a string method on the File, inside a promise that never settles — the MAME pass found this the hard way). Hand it a plain blob URL and the file lands under a random UUID name — but the a5200 core looks for one exact name, 5200.rom. So the page does this: whatever your BIOS file is named, the page wraps its bytes — untouched — as the single entry of a small zip built in the page, the entry named 5200.rom, and hands the frontend that zip's blob address. The frontend unzips it into place under the right name, and the machine wakes. Nothing is uploaded; the zip exists only in the tab's memory. The audit proved the mechanism by contrast: the same fixture cartridge, driven through the same page — with the real BIOS, it booted and answered its keys; with a 2,048-byte file of zeros in the BIOS slot, the screen stayed black. The firmware is genuinely required, and genuinely delivered.

What a5200 and EmulatorJS are

a5200 is the Atari 5200 core in the Atari800 family — the same emulation lineage that has modelled ANTIC, GTIA and POKEY for decades — packaged as a libretro core. EmulatorJS is the frontend the SNES, DOS, MAME and 7800 consoles on this shelf already carry: it loads the core, owns the screen, the save states behind the challenge baton, and the keyboard map. The frontend deals in RetroPad buttons; what each button does on a 5200 — stick, triggers, keypad — is the core's business, and it was measured for this console separately, as the standing rule requires.

The license question, in plain words

Two licenses ride with this console, both carried verbatim in the rack. The frontend is GPL-3.0, the same text the sibling racks carry. The core is GPL-2.0 — the a5200 project's own license. As with the 7800's core, the npm package ships no license file (its package.json license field is literally the string “License.txt”), so the GPL-2.0 text in this rack was fetched from the core's own repository, EmulatorJS/a5200, where License.txt sits at the root — 18,008 bytes, sha256 63755afa…896 — and is carried byte-for-byte. And the absence that matters most is stated plainly: no BIOS, no cartridge, and no game data of any kind is in the rack or the page.

The threading verdict — this one runs on the plain site

The DOS Console beside this one is exhibit-only on the website: its core ships threaded builds only, threaded builds need cross-origin isolation, and a static host can't send the headers. This core is not in that cage, and the verdict is measured, not inferred:

  • The core package ships a non-threaded payload alongside the threaded ones, and its build report declares no options and no thread requirement.
  • The frontend's own requires-threads list, read in its shipped source, is exactly ["ppsspp", "dosbox_pure"] — this core is not on it.
  • The console page therefore never sets EJS_threads, and the audit booted it on a plain local server with window.crossOriginIsolated === false asserted in the page — no COOP/COEP headers anywhere — and played it; the server's log shows the frontend selecting a5200-legacy-wasm.data, the non-threaded build. This console runs on GitHub Pages as Pages serves today.

The audit — refusal first, then a boot through a real BIOS

No commercial ROM was used, and none is kept. The audit cartridge is a synthetic .a52 built for this pass: 32 KB of hand-assembled 6502 that builds a blank ANTIC display list and paints GTIA's background register one colour per input — stick deflections read from POKEY's potentiometer registers, the trigger from GTIA, the second button and the keypad from POKEY's keyboard status. Driven through the shipped page, in order:

  • The refusal. Cartridge in, BIOS slot empty, Start pressed: the page printed the refusal quoted above and the machine did not boot. Measured.
  • The size warning. A 100-byte stand-in in the BIOS slot: the page named the size and the correct 2,048 in plain words, and the warning stays on screen. Measured.
  • The boot. The audit's BIOS (fingerprint above) in the slot, Start pressed: the machine booted through its firmware to the fixture's screen, and the fixture answered its inputs. A zero-filled 2,048-byte BIOS, same drive, gave a black screen — the contrast that proves the firmware path. Measured.
  • The stick. All four directions painted their own stable colours from the potentiometer registers — the core turns the digital arrow keys into full deflections of the analog stick, which is exactly the bend the page's Help names. Measured at the cartridge.
  • Fire 1 (Z) painted its colour from the trigger register. Fire 2 (X) painted its colour from POKEY's shift witness — the core models the controller's top button the way the real controller wires it, as the keypad matrix's shift line. Both measured at the cartridge.
  • The keypad. Every key the page prints — START (Enter), PAUSE (V), # (A), * (S), 0 (E), 1 (R), 3 (Tab), 9 (Q) — produced a real key-down event at the cartridge: POKEY's key-pressed status cleared and the fixture left its idle cycle for the key branch, for each key in turn. Events measured at the cartridge.
  • The baton. A state exported mid-run came to 350,347 characters under the 5200STATE1: prefix and imported back to the same machine state. The 5200's states are the shelf's largest — the Atari800 lineage saves the whole machine — and the page says so before you copy one.
  • The wire. The request log for a full session shows every fetch same-origin except the one external call named in the honest notes. The screen box is 840×630, the 4:3 the page's guard keeps. The file:// guard was driven too: lone file, locked slots, plain words.

The one thing the audit could not measure — said plainly

The keypad's per-key identity — that this key is “3” and that one is “#” — could not be read back at the cartridge. Three fixture designs tried: polling POKEY's key-code register directly, watching its status register, and capturing the code in a keyboard interrupt handler. The core delivers keypad events on POKEY's own scan timing (its source says so, in so many words: events are generated as the scan lines pass), and a cartridge that simply polls sees the latch and the ghosting between the 5200's four connected scan lines, not a clean per-key code. What the audit did establish at the cartridge is that every printed key arrives as a genuine keypad event (above). The names on those keys rest on the core's own published input map — its libretro descriptors and source, read in full during this audit — not on a cartridge measurement, and this lesson marks the difference rather than blur it. The remaining digits (2, 4, 5, 6, 7, 8) are not on the keyboard at all in the core's map: they live on a gamepad — the right stick's directions and the L3/R3 buttons — which the page's keys grid says out loud.

The analog bend

The real 5200 stick is an analog device: it reports how far, and it does not spring back to centre. No keyboard can bend like that — an arrow key is full deflection or nothing, and the audit's fixture read the pots at their extremes to prove that is what the core delivers from keys. Games written for a gentle touch (the missile-defence and paddle-flavoured ones) play hotter on keys. A gamepad's analog stick is the closest hand: the core reads it as true potentiometer values, centre where you leave it. That judgment — how the stick feels — is Steven's to make with his own cartridge in the slot; the audit can only certify the signal path, and it has.

Honest notes

The one phone-home attempt. The frontend, unmodified, tries once per session to fetch a version file from cdn.emulatorjs.org. It is upstream's own update check — the sibling audits met the same call — it carries no data about the player, the cartridge or the BIOS, it is not needed for play, and offline it simply fails. It is named here because “zero external requests” would otherwise be a claim this page couldn't keep.

A wrong BIOS fails dark. The machine gives no error of its own for a bad firmware file — the screen simply stays black, as the audit's zero-filled drive showed. The page's defences are the size warning at the slot and this note: right size (2,048 bytes), right machine, bare file not a zip.

.car files are not accepted by this core (its own list is .a52 and .bin) — the slot says so, and a .car image needs converting before it can ride here.

The audit's BIOS is gone. It existed only in the audit's scratch space, was never in the repository tree, and was deleted when the audit closed; the deletion was verified. The fixtures — synthetic, written for this audit — were never in the tree either.

The audit's ground. Drives ran headlessly against a plain local server — Steven's environment lesson (he opens lone files and real sites, not served folders) is answered by the file:// guard being driven too, and by the live-site verification recorded in the wiring receipts. His own library remains, as ever, the final receipt: his first 5200 cartridge with his own BIOS, and his call on the analog stick's feel, are still his to give.
