BUILDING A LESSON PACK FROM THE TEMPLATE
=========================================

A pack is a C: drive with a starting state. Building one is
bench work, not web work - the template carries the shape so
the author only builds the drive.

1. COPY the folder packs/pack-template/ and rename the copy
   pack-NNN-your-slug (NNN is the next number in the room).

2. BUILD THE C: inside drive/. That folder IS the drive root:
   AUTOEXEC.BAT, folders, and files sit there exactly as they
   should sit on the student's C:. Plant the starting state -
   the fault, the half-finished install, the scenario files.
   Everything in the pack must be ours or free. Commercial
   software is bring-your-own-media, always. REGISTER.TXT
   rides along from the template - it is the pack's shareware
   note, the only place the tip jar is mentioned. Leave it in.

3. WRITE THE SCENARIO into drive/README.TXT (the bracketed
   slots show the shape). The student reads it on the drive,
   with TYPE, before anything else.

4. WRITE THE COURSE into drive/TUTOR.BAT. The engine is
   already there: stages that say, pause, check (IF EXIST),
   advance or hint. Replace the stage text, the proof files,
   and the hints with your course. One task per stage. A
   student who can watch their own work pass a check learns
   faster than one who reads about it.

5. ZIP THE DRIVE'S CONTENTS - the files and folders INSIDE
   drive/, sitting at the zip's root, folders first - as
   pack-NNN-your-slug.zip beside the folder. (Not the folder
   itself inside the zip: the zip IS the drive.)

6. THE LESSON PAGE carries the bench talk around the pack:
   the scenario, the method, the audit receipts, the honest
   bends. Pack 001's lesson is the pattern to copy.

7. WIRING (Muse does this part): shelf entry, Full Index,
   sitemap, provenance, the room ZIP, the gate. Note for the
   wiring: this repo ignores new .zip files under projects/ -
   pack zips are force-added (git add -f) or the download
   link 404s. Learned on Pack 001, the honest way.

ONE MACHINE TRUTH WORTH KNOWING
===============================
A tutor's IF EXIST check sees what DOS sees. A file a student
creates INSIDE the machine (COPY CON, COPY, MD) is seen at
once. A file copied into the drive folder from outside while
the machine is running is not - DOS cached the directory at
mount time. The Workbench types RESCAN after its own copies;
a student who edits the folder mid-lesson should remount.
Design checks around work done inside the machine and this
never bites.
