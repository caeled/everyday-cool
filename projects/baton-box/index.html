The Baton Box 📦

A small relay server for pass-and-play games — games you play together, but not at the same time. One person (the host) runs the box on their computer. It keeps every game's place: whose turn it is, and the game's current state blob — a chunk of text the game itself makes when you export. The box never reads inside the blob. Players open the box in any browser on the same network, take their turn in the game, paste the new blob back, and the baton passes to the next player. Turns can take five minutes or five days.

The box understands no game. Any game that can pack its state into a blob and say whose turn is next can ride it. The Relay — the asynchronous Courier Bot game from Nerd Heaven — is passenger number one, not the only one. The download below is this whole project as a ZIP: unzip it, and the folder is the install.

How a session flows

Host starts the box → players join with a 6-letter code → the box says whose turn it is → that player copies the blob, plays their turn in the game, exports → pastes the new blob back → the baton passes → repeat until the game is won.
🏠

Create

Start a session

From the box's home page: pick the game, name the session, list the player names in turn order, and optionally paste a first state blob. Leave the blob blank and the first player simply starts a fresh game in the game page and hands back the first blob — the box handles both.

🔑

Join

Type the code

Players open the host's address in any browser and type the session's 6-letter code. The session page says, big and clear, whose turn it is — no accounts, no passwords, nothing to install on the players' side.

🎮

Take a turn

Copy, play, export

The session page shows the current blob with a one-tap Copy button and numbered steps: copy the code → open the game (the box serves it, too) → use the game's Import → play your turn → use the game's Export Code.

🏃

Hand back

Pass the baton

Paste the new blob on the session page and tap Hand it back. The box stores it, remembers the last 10 blobs, and advances the turn to the next player. If the session changed while you were playing, the box refuses with a plain-language warning and lets a human choose — nothing is silently overwritten.

For the host — setting up (about 5 minutes, once)

  1. You need Python 3 on the host computer (a Windows, Mac, or Linux machine that can stay on while you play). On Windows, if Python is missing, get it free from python.org → Downloads, and during install tick the box “Add Python to PATH.” Macs and Linux usually have it already, or install it the same way.
  2. Put the baton-box folder somewhere simple — the Desktop is fine — and keep its files together.
  3. Start the box: on Windows, double-click start-baton-box.bat. Anywhere else, open a terminal in the folder and type python baton_box.py (on some systems: python3 baton_box.py).
  4. A window opens with friendly writing and some addresses. Leave that window open — that window is the box. Closing it (or pressing Ctrl+C) puts the box away; your games are saved in the folder and come back next time you start it.
  5. The box's home page shows the address to give players (it looks like http://192.168.1.20:8917 — your numbers will differ). Players must be on the same Wi-Fi or network as the host computer.
  6. Start a game from the home page, then tell the players the address and the 6-letter game code. That is the whole setup.

School and office networks sometimes block computers from seeing each other. If players cannot open the address, a home network or a phone hotspot for the host usually fixes it.

For players — joining and playing

  1. Connect to the same Wi-Fi as the host.
  2. Open the address the host gave you in any browser.
  3. Type the game code and tap Join.
  4. The page tells you whose turn it is. If it is yours: copy the code, open the game, paste it into the game's Import, and play your turn.
  5. When your turn is done, use the game's Export Code, come back to the game's page in the box, paste the new code, and tap Hand it back. The next player's name lights up. Done — go live your life; the box will keep your place.

The honest limits

Same network by default. Players must reach the host's machine (same Wi-Fi/LAN). The box is not on the internet unless the host deliberately puts it there.

The host machine must be on, with the box window open, while anyone loads or hands back. Between turns it can sleep for days — the state waits in sessions.json.

Honor system, not a bank vault. No passwords. Anyone on the network with a session code can view that session's blob and hand back a turn. Never put secrets in a state blob.

The box doesn't know any game's rules. A nonsense blob is carried faithfully and only rejected by the game on import — like a good baton, it just gets carried.

The contract, in one breath — for future games

A session is {gameId, code, title, players[], turnIndex, state, updatedAt, history}. The box stores and forwards; it never parses state. A game qualifies if it can (1) pack its state into a text blob, (2) list its players in turn order, (3) serve one page that imports and exports blobs, and (4) drop a tiny manifest.json in games/<game>/. Adding a game takes no changes to baton_box.py — the self-test proves it with a dummy game registered by manifest alone. The full contract, the manifest format, and the JSON API are in CONTRACT.md, inside the download.

Help ▾ — the full notes, in one place

What the Baton Box is

The Baton Box lets people play a turn-based game together but not at the same time. One person runs the box (the host). Everyone takes turns in a game, and the box remembers whose turn it is and keeps the game's place, using a code the game itself makes. It is one Python file (baton_box.py) using only the standard library — no dependencies, no build step, no internet needed. Default port 8917 (override with the BATON_BOX_PORT environment variable). Sessions are stored in sessions.json beside the script, written atomically after every change, so games survive the host restarting.

When something looks wrong

  • The page will not load. Check you are on the same Wi-Fi as the host, and that the host's box window is still open. Ask the host to read the address off the box's home page once more — one wrong digit is the usual culprit.
  • “This game moved while you were playing.” Two people played from the same starting code. Talk it over like players, not like computers: whoever hands back second can choose to replace the first turn, or reload and replay from the newest one. No harm done — the box keeps the last few codes, and the host can see them.
  • A code will not paste into the game. Make sure you copied the whole code (they are long — that is normal) and that you are pasting the newest one from the game's page in the box.
  • The host computer restarted. Start the box again. Games are saved in sessions.json in the baton-box folder after every hand-back. That file is your backup — the host can copy it somewhere safe now and then.
  • Forgot the game code? It is on the game's page in the box, and the host sees every game on the home page.

The honest limits

  • The box works on your own network. It is not on the internet unless the host deliberately puts it there.
  • The host computer must be on and the box window open while anyone is playing or handing back. Turns can wait as long as they like in between — days is fine.
  • There are no passwords. Anyone on your network with a game code can see that game's code and take a turn. It is an honor-system game box for people you like — not a bank vault. Never put secrets, passwords, or private information inside a game's state.
  • The box does not know the rules of any game. If a code is nonsense, the game will say so when someone imports it; the box just carries codes faithfully, like a good baton.

Files in the download

  • baton_box.py — the whole server: storage, API, and all pages (home, session, help, host list), inline. Python 3 standard library only.
  • start-baton-box.bat — the Windows double-click starter.
  • games/the-relay/ — passenger number one: The Relay client (a copy the box serves) and its manifest.json.
  • games/the-dos-console/ — passenger number two (boarded 26 November 2026): the DOS Console, page and EmulatorJS rack, a copy the box serves with the cross-origin isolation headers its core needs — the console's playable home.
  • CONTRACT.md — the contract for future game authors, the manifest format, and the JSON API.
  • selftest.py — an end-to-end HTTP self-test: python3 selftest.py proves the whole loop in a throwaway folder (20/20 checks — see the lesson).
  • sessions.json — created at runtime; every session, written after every change. This is the backup file. Delete it to empty the box.
