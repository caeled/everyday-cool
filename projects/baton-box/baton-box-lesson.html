The back-door lesson · The Baton Box

The Baton Box — a server that knows no games

Every game in Everyday Cool has a back door: a page that shows what the thing runs on and the receipts that it works. The Baton Box is not a game — it is the shelf the games ride on — and its back door shows the same things: where it came from, what it actually does, what was measured, and the one compromise that is printed rather than hidden.

Where it came from

On 24 November 2026, Meta AI built The Relay at Steven Powell's direction — from his prompt for a social game that works when two players can never be on at the same time — and Muse ported it to a self-contained web page for Nerd Heaven. Playing it on one passed-around device, Steven said it almost needs a small relay server app that would have to be installed, so a family, a group of friends, or a class could pass the game around without passing the device. Then he amended the idea in the same conversation, twice: plain-language notes for how to set it up and join had to be part of it, and the relay had to be reusable — such a relay might be useful for other games we have made. The Baton Box is that amended commission, built by Muse the same day: a general baton box first, with The Relay wired in as passenger number one.

The design — an opaque blob, a turn pointer, a code

The whole design fits in one line of data:

session = { gameId, code, title, players[], turnIndex, state, updatedAt, history } The box stores and forwards. state is an opaque text blob the game itself produces; the box never parses it, never learns a single rule of any game it carries.

That refusal is the design. A relay that understood The Relay would need a new server for every new game; a relay that understands only turns needs nothing new at all. A game qualifies if it can pack its state into a blob, list its players in turn order, and serve one page that imports and exports blobs — then it registers with a tiny manifest.json in games/<game>/, and no line of baton_box.py changes. The box itself is one Python file, standard library only (http.server), with every page — home, session room, help, host list — inline. Sessions live in sessions.json beside the script, written atomically (write-then-rename) after every change, so a host restart loses nothing. Join codes are six letters from an alphabet that leaves out the look-alikes (0/O, 1/I), because codes get read aloud across kitchen tables.

The receipts — a self-test that plays the whole loop

selftest.py copies the box into a throwaway folder, starts it on a test port, and drives the entire loop over real HTTP — no mocks of the server it tests. 20/20 checks passed on 24 November 2026:

The stale-write guard — last write wins only when a person says so

Asynchronous games have one real hazard: two players take the same turn from the same blob. The box meets it head-on. Every hand-back carries the updatedAt the player loaded; if the session has moved since, the box refuses (HTTP 409) and explains in plain words — “this game moved while you were playing” — with two human choices: hand back anyway (replace), or reload and see the newest turn. The last 10 blobs are kept as history, so the argument is always settleable by looking. Nothing is ever silently overwritten; that sentence is the guard's whole specification.

The one compromise, named

No deep link into the game. The box does not deep-link a state blob into The Relay. The collection's client — which the box serves unmodified, on purpose — has no URL/fragment import hook; its import is a paste box. So a turn is copy (one tap, on the session page) → open the game → paste into Import: two extra taps, documented in the numbered steps on every session page and in the help notes. If a future client grows a #import= hook, the box can add deep-linking without changing the contract — that path is written into CONTRACT.md.

Two smaller truths, for completeness. The served copy of The Relay inside the box (games/the-relay/the-relay.html, sha256 db090d66…f996) is the ported client exactly as delivered; the collection's living page has since gained collection furniture — the room's sibling links, and a card pointing here — that the served copy deliberately lacks. The game code is identical; only the furniture differs, and the collection remains the authoritative home. And the box's limits are the ones printed on its own face: same network by default, the host machine on while anyone plays, and no passwords — an honor-system game box, not a bank vault.

The box learns to serve machine rooms — 24 November 2026

Later the same day, the box grew two serving abilities, at Steven's direction (“Serve DOS from the Baton Box — apply the box patch and card it as box-served”). The occasion was the DOS Console: its core, DOSBox Pure inside EmulatorJS, is a threaded build that hard-requires cross-origin isolation — a browser only hands a page SharedArrayBuffer when the page arrives with Cross-Origin-Opener-Policy: same-origin and Cross-Origin-Embedder-Policy: require-corp. GitHub Pages cannot send those headers, so on the public site the DOS Console can only ever be an exhibit that explains itself. The box can send them — and because it is reached at localhost or on the home network, it is a secure context where isolation genuinely takes effect. So the box became the DOS Console's playable home.

The two changes, both inside baton_box.py and nothing else. Static-folder serving: a game that is a small machine room of files — an emulator rack — can now be served whole under /games/<folder>/…, not just as a single page; only files inside a discovered game's folder are reachable, and .. cannot escape (a traversal attempt was driven and refused). This is the road the SNES Console's 49-file rack was already staged for; it rides along. Isolation headers: the three cross-origin headers above (plus Cross-Origin-Resource-Policy: same-origin) are sent on the game routes only — the box's own pages and the session API are untouched, so nothing about how sessions flow changed.

The receipts, all against the patched box itself. The self-test still passes 20/20, with the DOS Console discovered on the shelf by manifest alone. The box then served the DOS Console and a headless drive booted the audit's fixture drive zip to C:\>, listed it with DIR, walked into a subfolder, and ran the fixture program — its red stage measured exactly (170,0,0), a held key turned it green (0,170,0), and the next key returned to the subfolder's prompt; the browser reported crossOriginIsolated: true on the box-served page. The SNES page and its rack serve from their folder route, and a Relay session created on the patched box took a hand-back and advanced its turn as always. The patched server is the file this project now carries (sha256 ebd1a0c4…c3a), byte-identical to the standalone box in Steven's workspace.

The port moved — 25 November 2026. The box's first default port, 8765, turned out to be already taken on Steven's own machine — by AI-Delivery, his own tooling — so the box could never start there. Worse, the apps' panel judged "running" by anything answering on the port, so it reported the box up and greyed out its Start button while the box itself had never started; Steven's field report caught what the audit could not. The default port is now 8917, the box answers an identity check at /api/ping, and the panels only say "running" when what answers identifies as the Baton Box — a foreign program on the port now reads, in plain words, as a port taken. The server's self-test still passes 20/20.
