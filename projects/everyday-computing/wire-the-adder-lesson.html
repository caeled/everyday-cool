Wire the Adder — the lesson

Wire the Adder is a wiring game: six levels that start with choosing the one gate that matches a truth table and end with a two-bit adder you chained together yourself, out of nothing but gates. This page is the other half of it — what a gate actually is, why the truth table is the whole contract, the game's own constructions worked out in full, and how the game is built — readable while you play, from the 📖 Lesson button in the game.

The subject — a gate is a switch rule

One rule, never broken

A gate is a tiny rule with wires. It reads one or two bits — a bit is a single two-way choice, 0 or 1 — and answers one bit, by a rule it never breaks. AND answers 1 only when both inputs are 1. OR answers 1 when either is. NOT, the only gate with a single input, flips whatever it is given. Physically, a gate is a handful of transistors: switches with no moving parts, opened and closed by voltage instead of fingers. Everyday Computing's gates bench lets you flip the switches and watch the lamp obey; the game takes the same six gates and hands you the wiring.

The truth table is the contract

Every gate — and every circuit, however big — can be described completely by its truth table: one row for every possible combination of inputs, and the output the circuit must give for each. Two inputs means four rows; the table is, in the room's words, the gate's whole biography, four lines long. That makes the table a contract. If your circuit's output matches the target table in every row, your circuit is that function — it doesn't matter which gates you used or how you wired them. And if it disagrees in even one row, it isn't, yet. The game grades nothing else: no style points, no partial credit for a beautiful near-miss. Match the table and you have built the thing; that is what "built" means for circuits, and it is why a machine can check your work at all.

Read the XOR row until it feels obvious: 0, 1, 1, 0. That little pattern — lights when they differ, dark when they agree — turns out to be the sum bit of addition, which is the whole reason this game exists.

The math the game runs on

Gates have a written algebra, with ∧ for AND, ∨ for OR, ¬ for NOT, and ⊕ for XOR. Stated the way the game's checker states them, the constructions are four short formulas:

A ⊕ B  =  (A ∨ B) ∧ ¬(A ∧ B) XOR built from the basics — the game's Level 2. "Either, but not both": OR says at least one, the flipped AND says not both at once, and AND-ing those two answers leaves exactly "they differ."
Sum = A ⊕ B   ·   Carry = A ∧ B The half adder — Level 3. The sum bit is 1 exactly when the inputs differ; the carry is 1 only when both are 1, the single case that overflows one column: 1 + 1 = 10.
Sum = A ⊕ B ⊕ Cin   ·   Cout = (A∧B) ∨ (A∧Cin) ∨ (B∧Cin) The full adder — Level 4. The sum bit is 1 when an odd number of the three inputs are 1; the carry-out is 1 when at least two are. Read those two outputs together, Cout first, and they are the count of 1s written in binary: 00, 01, 10, 11 for zero, one, two, three. A full adder is a counting machine that reports its count in binary.
rows = 2n n inputs make 2n truth-table rows: 2 inputs → 4 rows, 3 → 8, the finale's 4 → 16. Exhaustive checking — trying every row — is only possible because n stays small. At n = 64 (a real adder's width), the table would have about 1.8 × 1019 rows; a checker testing a billion rows a second would need roughly 585 years to finish one circuit. Real chip verification uses cleverer mathematics; this game keeps n at 4 or below so the whole contract always fits on one screen, checkable by eye.

Worked examples — the game's own levels, solved in the open

Example 1: Level 2 — XOR from four basic gates, every wire shown

The construction the game asks for, and the room's logic builder demonstrates: Gate 1 is OR(A, B) — "at least one." Gate 2 is AND(A, B) — "both." Gate 3 is NOT on Gate 2 — "not both." Gate 4 is AND(Gate 1, Gate 3) — "at least one, and not both." Walk all four rows:

ABGate 1: A ∨ BGate 2: A ∧ BGate 3: ¬(Gate 2)Gate 4: Gate 1 ∧ Gate 3XOR says
0000100 ✓
0110111 ✓
1010111 ✓
1111000 ✓

The last two columns agree in every row, so the contract is met: four gates from the basic bin do precisely what the single XOR gate does. Notice where the work happens — Gate 3, the NOT, is what carves the "both" case out of OR's "either." Without a flip somewhere, it cannot be done (that story gets its own section below).

Example 2: Level 3 — the half adder's whole table

11011 + 1 = 2 — written 10: a carry and a zero

Two gates sharing the same two inputs, each answering a different question about them. That is the entire invention; everything else in this game — and in a processor — is chaining it.

Example 3: Level 4 — the full adder, and the carry is a vote

Now read only the Cout column: it is 1 in exactly the rows where at least two of the three inputs are 1. That is a majority vote — which is why Level 5 asks you to build majority on its own, and why the game's full adder wires its Cout as (A∧B) ∨ (A∧Cin) ∨ (B∧Cin): the three possible pairs, any one of which settles the vote. And read the Sum column: it is 1 when the count of 1s is odd. Sum is the count's low bit; Cout is its high bit. Addition, at bottom, is counting carefully.

Example 4: Level 6 — 3 + 2 = 5, one ripple

A is 11 (three), B is 10 (two). The low column adds A0=1 and B0=0 with a half adder: S0 = 1, carry 0. The high column is a full adder taking A1=1, B1=1, and that carry of 0: S1 = 0, Cout = 1. Read the outputs in order — Cout, S1, S0 — and you get 101, which is five. At the other end of the table, 3 + 3 runs the same ripple with a carry that does fire in the low column (1 + 1 there gives S0 = 0, carry 1), and answers 110 — six. Sixteen rows, sixteen honest sums, all of them produced by seven gates whose individual rules fit on an index card.

Why NOT is special

Five of the six gates combine; NOT inverts, and inversion is the ingredient everything else is missing. Three consequences, each one load-bearing:

  • Without a flip, some functions are unreachable. AND and OR are monotone: turn an input from 0 to 1 and their outputs can only stay put or rise. Wire ANDs and ORs together in any arrangement you like and the whole circuit stays monotone — so it can never compute NOT, and never XOR either, since XOR's output falls when the second input rises to meet the first. Level 2 is impossible without Gate 3. The flip is not a convenience; it is what makes the gate set complete.
  • NAND and NOR are universal because they smuggle the flip inside. Each is a combining gate with a NOT on its output, and either one alone can be wired to imitate all six gates — which is why real chips are built from NAND or NOR by the billion.
  • Inversion is what makes memory, and clocks, possible. Wire two NOR (or NAND) gates in a loop, each feeding the other, and the pair settles into one of two stable states and stays there — it holds a bit. That cross-coupled pair is the seed of all computer memory. Wire an odd number of NOTs in a ring instead and the loop can never settle: each gate keeps flipping the signal it just received, forever — an oscillator, which is where a computer's clock comes from. Both tricks need wires that loop back, which this game's columns deliberately forbid; the room's free-form logic builder allows them, and answers ? for a loop, honestly, because a loop's answer is a behaviour in time, not a row in a table.

How it's built — the coding choices

The circuit is data: a netlist

The game stores a circuit the way engineers do — as a netlist, a list of parts and wires rather than a drawing. Each gate is one small record: a rule name ('XOR') and, per pin, a source string — 'in:A' for a switch, 'slot:2' for Gate 3's output, 'const:1' for a constant, or 'none' for an unwired pin, which reads 0 the way a loose wire reads nothing. The evaluator that runs it is short enough to hold in your head: walk the gates in order, resolve each pin's source to a 0 or 1, apply the rule, write the answer down for later gates to read.

Columns make one pass enough — and loops impossible

Gates sit in columns, and a pin may only name a switch, a constant, or a gate in a strictly earlier column. That one rule does three jobs. It keeps the wiring flowing left to right, so the board reads like the signal moves. It means the evaluator never has to iterate or solve anything: by the time a gate is evaluated, everything it reads has already settled, so a single pass gives the final answer. And it makes feedback loops inexpressible — there is no string you can put in a pin that names a later gate — so this game never faces the builder's honest ?. The latch and the oscillator live outside this game's rules on purpose: a truth table can only grade circuits that hold still.

The table in the game is the checker, not a picture of it

The logic lives in one sealed block of code, fenced between marker comments (/* === CORE === */ and /* === END CORE === */), with no reference to the screen: gate rules, the evaluator, the table builder, the level data. The truth table you watch while playing is produced by that block, live — for every change you make, the checker runs your circuit against all 2n rows and lights each one. There is no separate, friendlier grading logic that could drift away from the real one.

The proof, run before shipping

Before this game shipped, a script lifted that exact core out of the shipped file and ran three checks through the game's own evaluator: every level's reference wiring passes its full truth table (44 rows across the six levels); every level's starting wiring fails — no level begins already solved; and on Level 1, each wrong gate in the bin fails the table while XOR alone passes. The tables themselves were spot-checked a second way, from ordinary integer arithmetic — the half adder's 1 + 1 → Sum 0, Carry 1; the finale's 3 + 3 = 6 → Cout 1, S1 1, S0 0 — so the contract was verified independently of the code that generates it. The solutions the proof uses are stored in the level data and never shown in the game; they exist so "solvable" is a receipt, not a hope.

Simplifications, named

Stated plainly: the gates here switch instantly. Real gates take a small but nonzero time to change state, and while a real circuit's inputs are mid-change its outputs can briefly glitch — flash the wrong value for an instant (engineers call these hazards). This game has no time in it at all, so there are no glitches and no races; the full adder's carry "ripples" in zero time, where a real ripple-carry adder genuinely waits for it, column by column — the delay real designers pay faster adder designs to avoid. One gate's output here can feed any number of pins; a real output weakens as it drives more inputs (fan-out is a real budget). Unwired pins read a clean 0; a real floating input is undefined and picks up noise. Inputs are perfect 0s and 1s, never the in-between voltages a real signal passes through on every switch. And the gates never break, overheat, or draw current — the only cost of a gate in this game is the slot it sits in.
